# 识途前端验收

按本次变更的影响面选择最低充分的验收级别，验证实际效果与业务能力。仅用于识途 / Cairn；先确认当前仓库有 `docs/design/front/`。下文路径均相对仓库根目录。项目技术选型与规范从仓库读取，不绑定某一种浏览器工具。

## 先定范围，再选级别

确认用户要求与本任务改动，检查涉及的组件及必要调用方；工作区其他未提交修改不自动纳入范围。已有交付证据与检查结果可复用，不因加载本 skill 重新跑一遍。

| 级别 | 典型变更 | 最少足够的验收 |
| --- | --- | --- |
| 轻量 | 按钮文案、一个图标、无语义变化的日期外观或数字分隔、孤立装饰 | 看本次差异和相关用例；有格式逻辑时检查代表值与边界；可能截断时局部查看。通常不启动浏览器，不新增截图或完整验收报告 |
| 局部 | 按钮行为 / Loading / Disabled、单个表单或弹窗、局部分组、数据语义转换 | 验证被改组件的实际结果与相关边界；有 UI 交互就操作所在页面，需要时检查键盘与窄屏。只测与这次修改有关的路径 |
| 页面或底座 | 新业务页面、复杂工作区、导航、公共 Token、影响多处的 UI 组件 | 新页面覆盖核心任务与适用异常；公共变更选有代表性的调用页面，通常一个管理页加一个工作区；检查相关断点、状态及截图 |

按行为和影响面分级，不按改了几行分级。下面的“小改动”需要升级，但仍只验证关联范围：

- 日期涉及时区 / 排序 / 调度，金额涉及精度 / 单位 / 空值：至少局部语义检查，可用纯逻辑测试完成的部分不强制浏览器。
- 按钮改到提交、取消、删除、权限或副作用边界：操作结果与安全取消路径需要检查；只改该按钮的文案不因此升级。
- 共用 Button / Input 或全局 Token 一行变化可能影响多个页面；只改某个调用处的图标不做全局验收。

确认是轻量改动后即可按轻量级结束，不自动升级为本 skill 后续全部步骤。级别清楚时自行决定，不要求用户每次选择。

## 只读取相关依据

- 任务与布局：`docs/design/front/ai-workflow.md`。
- 控件状态：仅查 `docs/design/front/components.md` 中被改组件；色彩和尺寸查 `tokens.css` / `design-language.md`。
- 视觉方向：`docs/front_design/2026-09-13-foundation-lab/index.html` 已获用户认可；真实 React 样板迁移进度见 `docs/spec/2026-09-13-ui-foundation-review.md`。

原型是视觉与交互参考，模拟 API、证据画面、成功结果不能作为真实能力证据。无需每次打开全部规范、复盘全部设计历史或重新生成原型。

## 验收两件事

**业务能力是否成立。** 从用户动作验证到实际可观察结果，不能止于按钮可点击或出现 Toast。按本次功能选择：表单值是否写入正确对象、请求参数和权限是否正确、错误后输入是否保留、重复提交是否受控、历史快照与证据是否对应。前端 fixture / mock 只能证明前端契约，真实后端联调未执行时注明，不把两者混为一项通过。

**呈现是否帮助用户完成任务。** 对照认可方向检查主操作、信息层级、状态语义、字段可读性、当前选择与上下文。布局或样式有变化时实际查看浏览器渲染，必要时截取相关区域；检查它是否变好，不只检查“有无报错”。原型无需逐像素复制，真实数据、可访问性与业务准确性优先。

选择和改动相关的检查，不展开无关清单：

- 交互组件：适用的正常 / 聚焦 / 加载 / 禁用 / 错误状态；涉及弹层时验证关闭、取消和焦点返回。
- 布局：主要使用宽度；改变重排规则时加一个受影响断点。公共布局变更再覆盖 1366 / 1440 / 1920 和窄屏，不要求单个文案修改全分辨率截图。
- Run / Evidence：分别判断 Run、StepRun、Attempt 和证据完整性；副作用不明不盲目重放；刷新后的真相来自持久化状态。
- Scenario：Target 绑定、顺序编辑、AI 建议显式接受与冻结快照。
- Target / Account：控制台身份、目标账号、认证、会话与租约的正确区分。

## 成本与工具边界

优先复用已运行的预览、已有浏览器会话、项目测试与 fixtures；需要浏览器时再启动环境。打开真实控制台前先跑 `pnpm check:stack`（或 `pnpm check:stack web`）。栈未起来不得把 mock / 单测写成页面验收通过。可用项目现有 Playwright / Vitest，不为本次验收引入框架、批量脚手架或新依赖。

`pnpm check:design` 是现有的确定性设计检查，已接入 CI 配置。改到 Token、共用组件或布局时本地运行；仅改文案或展示格式无需在 skill 中重复运行整套。它验证源码规则与 HTML 样本，不能替代真实 React 页面的能力和视觉验收。

不自动运行全仓测试，不自动访问所有菜单，不对简单改动要求先出原型或另开验收任务。权限、删除、提交等动作优先用受控 fixture / 测试环境验证，不因“验收”扩大用户已授权的外部操作。

若环境缺失，完成仍可执行的局部检查，说明具体未验收项；不要把 mock 成功或静态截图描述成真实功能通过。

## 发现偏差与结束

按影响定位修复：公共视觉问题修 Token / 基础组件，局部拥挤修页面组合，状态错误修领域映射。当前任务包含修复时继续完成相关修复并复测；仅要求验收时给出问题、位置与证据，不顺带扩展改版范围。

相关检查通过且没有未解决疑点就停止。只因新修改、失败或实际疑点扩大范围；不为“更放心”重复测试。已认可截图不能直接被新截图覆盖来消除差异，应先解释该差异是否预期。

结论按工作量缩放：轻量检查一句话；局部或页面验收给出级别与原因、验证结果、发现的偏差及具体证据路径、尚未验证的项目。没有问题时不生成长清单或逐项“通过”报告，也不宣称零偏差保证。
