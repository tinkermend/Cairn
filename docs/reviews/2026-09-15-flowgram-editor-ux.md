# FlowGram 编辑便捷性修正

日期：2026-09-15。范围：`codex/flowgram-sequence-spike` 验证分支，对应[接入草案](../spec/2026-09-14-flowgram-sequence-editor.md)。本次是页面级验收；正式接入方案仍待审。

## 判断与最终调整

这个工作区的首要任务是连续编写、检查和修改步骤。横向画布配模态属性抽屉会让连续编辑增加关闭与打开操作，打断步骤上下文；紧凑列表铺满宽度后，诊断彩色整行边框又放大了视觉干扰。已按用户反馈撤回这套布局。

恢复原有纵向画布 / 步骤列表和常驻属性的并排布局，保留原试跑结果区及窄屏步骤 / 属性 / 页面切换。仅补充共用步骤定位、上一项和下一项导航。定位后画布恢复实际大小并显示所选步骤；列表同步滚到选中项。正常点击、拖动选择仍沿用原路径。

橙色源自已有 `status-warning-foreground` Token，整行染边框则来自列表的诊断映射，设计规范没有要求它。现在普通步骤与提醒步骤使用同一中性边框，仅选中项显示蓝色选中状态。提醒使用小图标与计数，错误使用局部图标和明确文字；完整原因保留在属性区。CSS 定位质量提醒不等于执行失败，也不伪装成阻断错误。

## 便捷性的判断标准

| 任务 | 当前标准与验证 |
| --- | --- |
| 编辑相邻步骤 | 常驻属性，点击下一步后可直接修改，无须开关弹层 |
| 找到屏幕外的步骤 | 按序号和名称直接选择；同时定位画布与属性，不依赖反复拖动 |
| 在列表与画布间切换 | 保留选中 Step ID 和未保存字段，列表显示对应选中项 |
| 判断哪里有问题 | 区分提醒与错误；选中状态不被诊断边框覆盖；原因在对应属性中可读 |
| 调整顺序 | 拖动、按钮与既有快捷键是等价入口，结构修改可撤销 |

这组标准优先于横向或纵向的外观选择。后续若调整布局，应以同一组连续编辑任务比较操作次数、找错和恢复成本；不应仅凭一屏能放多少卡片决定方案。属性表单宽度和试跑结果占用仍沿用上版，本次没有扩展为新一轮工作区重构。
