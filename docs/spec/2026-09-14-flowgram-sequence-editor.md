# FlowGram Sequence Editor 正式接入方案（待审）

日期：2026-09-14。状态：**正式范围仍待审；用户已授权线性画布及本轮交互修正通过验收后合入主分支**。依据：[10 步混编验证报告](../reviews/2026-09-14-flowgram-sequence-spike.md)、[9/15 交互修正](../reviews/2026-09-15-flowgram-editor-ux.md)、[蛇形排布验收](../reviews/2026-09-15-flowgram-snake-layout.md)、[Sequence Studio 基础](2026-09-13-sequence-studio-foundation.md)、[前端工作流](../design/front/ai-workflow.md)。不新增开发阶段，交付顺序引用[主计划](../plan/识途开发路线与工程实施计划.md)。

## 1. 目标与选型

在现有 Scenario Studio 中增加适合顺序执行的可视画布，支持确定性步骤与 AI Action / Extract / Assert 混编。用户可以查看次序、编辑字段、识别数据引用、保存并试跑，继续查看持久化证据。

建议采用 `@flowgram.ai/fixed-layout-editor`。PoC 已验证 1.0.15 与 React 19.2.8 的局部桥接路径及真实运行；将其作为有条件首选。没有对 xyflow 做同等原型验证，因此不据本次结果宣称全面优于 xyflow。若正式接入只需要最小列表重排，保留已有列表也是有效选择。

本次正式范围是线性 Sequence；分支、循环、并行、自由连线和通用 Workflow Runtime 不在此范围。以后增加控制流必须先扩展领域契约与 Runtime，不能仅开放画布节点。

## 2. 数据所有权

| 信息或行为 | 归属 |
| --- | --- |
| Step ID、type、effectType、input/output、policy、provenance | 版本化 ScenarioDocument / Shared Runtime Schema |
| 结构与引用合法性、能力闸门 | 现有 Compiler、Capabilities 与服务端校验 |
| 属性表单、无效字段草稿、未保存提示、OCC | 识途 Studio 状态层 |
| 节点位置、连接线、缩放、拖放预览 | FlowGram |
| 插入、删除、移动、类型变更 | 识途结构命令，再投影到画布 |
| 运行状态、快照、Attempt、输出、Evidence | 现有 Run 生命周期及 SSE 观察接口 |

画布仅是投影。FlowGram JSON 不作为 Scenario 的持久化或执行格式，也不引入第二套变量与表单引擎。

## 3. 适配结构

增加独立 `SequenceCanvas` 组件、投影适配器、领域命令与视口适配层。业务页面通过明确 props 输入当前文档、选中 Step ID、诊断、权限和运行观察结果；通过回调提交操作。

- 导出投影保留 Step ID。导入拖动结果只接受已知 ID 的排列；字段从最新 ScenarioDocument 取值，防止旧画布状态覆盖表单。
- 插入和删除先通过 Studio 命令更新领域文档，再刷新投影，不能只操作 FlowGram 内存模型。
- 未知节点、重复/缺失 ID、分支 blocks、其他类型必须拒绝并恢复最后有效投影，给出可操作的错误提示。
- 重排不静默修复引用。Compiler 在消费步骤位于输出之前时报错，保留用户意图并阻止执行。
- 所有能力按已有角色权限和运行能力闸门开放。只读用户仍能查看节点和证据；保存/发布在途不接受结构变更。
- 运行结果按 Snapshot Step ID 匹配；当前定义变更后明确标识草稿与本次运行不同，不能把历史成功展示成当前草稿已验证。

草稿 GET/POST、试跑 POST、发布 POST 和 Run SSE 均沿用现有接口。本范围预计不增加数据库迁移或 Worker 执行能力。

## 4. 用户交互

2026-09-15 补充验证：用户确认“工字形”指横向排满后蛇形折行。评估同样视口与可读字号下的可见步骤数，保留常驻属性与原有纵向排布作为切换选项。折行只改变展示，Step ID、执行次序、插入与重排仍遵循原结构命令；转向处须有明确箭头，不能用视觉分组伪造执行分支。列表与画布统一两列编辑区，试跑结果下置，消除没有结果时仍预留第三列的空白。验证正常 / 长名称 / 窄屏、顺序与拖放、选中和草稿保留，并核对折行后密度是否实际改善。

2026-09-15 PoC 交互修正（按用户反馈，仅验证分支）：恢复步骤与常驻属性面板并排，保留原画布 / 列表切换和窄屏步骤 / 属性切换。主任务是连续编辑，桌面单击下一步即可编辑，不增加抽屉开关。长流程在同一工具栏按序号定位、前后切换；切换视图保留 Step ID 和未保存字段。步骤容器使用中性边框，仅当前选择高亮；诊断以局部图标和文字表达，完整原因继续在属性区显示。复用 Select、Button、Studio 草稿状态与现有 Token。验收覆盖 10 步真实样本、32 步前端布局样本、连续编辑与视图切换、重排撤销、诊断语义、只读和窄屏。横向画布加弹出属性的版本已按用户反馈撤回；正式方案仍待审。

默认入口在方案审查时确定：建议首轮通过开关开放画布，并保留列表作为回退。选中节点在属性面板显示同一 Step；连线加号打开已有步骤类型菜单。拖动有落点提示，并提供上移/下移按钮和键盘等价操作。

诊断显示在相关节点和字段，AI Extract 的输出与后续 from/fromField 保持可见。运行状态标注「试跑」，证据详情沿用原面板。窄屏按步骤、属性、运行页面切换，画布自身滚动；触摸操作不能依赖鼠标拖动。

视觉使用识途 Token 和现有 UI 组件，自定义 FlowGram 材料；不引入整套 Semi 主题。

## 5. 生命周期与撤销决策

PoC 中直接嵌入现有 StrictMode 会重复注册 `FlowRendererRegistry`。正式实现需在以下两条路径中确认一种：

1. 保留独立 React root 桥接，严格管理卸载、事件与显式状态输入，组件不依赖父树 Query/Router Context；增加重复挂载、长时运行和泄漏回归。
2. 形成最小上游补丁或采用已验证的上游修复版本，恢复普通组件嵌入；固定依赖及补丁的升级流程。

不得通过关闭全应用 StrictMode 消除问题。视口调用集中封装，显式传入 zoom，覆盖窗口缩放、隐藏后恢复和空文档。

PoC 沿用现有单次结构撤销。正式版应决定是否扩展多步撤销；若扩展，统一由领域命令维护，与字段草稿的保留规则一起测试。不能同时运行 FlowGram history 和 Studio history 两套事实源。

| 验收面 | 通过条件 |
| --- | --- |
| 契约与数据 | 所有开放 Step 类型往返不丢字段；输出引用、policy、provenance 保留；拒绝非法节点和控制流 |

## 7. 合入与回退

审查批准后，从独立 worktree 的基线之后提取本模块变更，适配届时主线，不能将工作区快照整批合并。保留异步加载和列表回退；关闭画布开关应不影响既有 Scenario、版本或 Run 的解释和执行。升级 FlowGram 必须重复兼容与结构往返检查。

此次草案没有授权或执行生产部署。正式实施完成后更新 CHANGELOG，并将验收结果单独记录到 docs/reviews。
