# D1：顺序编排与 AI 步骤编辑增强

日期：2026-09-13。状态：**本线已落地（ST02 / ST03 根键与 fromField / ST05）。ST01 由现有 `@cairn/shared` 契约消费，未另造生产 DTO。ST04 已挂载现有 AI 表单与证据组件，步骤库仍受能力闸门约束。ST06 / 真模型 / SSE / Live View 未宣称通过。**

本方案是现有 Scenario Studio 的增量，归属 P10 / P11，并消费 P7 运行查询与 P8 / P9 的 AI 契约。与 [Midscene 正式接入方案](2026-09-13-midscene-runtime-integration.md)在 D1 内并行；不新增里程碑，不调整 D2 录制回填、D3 可复用动作、D4 试点顺序。交付顺序与两条线的安排只维护在[工程计划第 5 节](../plan/识途开发路线与工程实施计划.md#5-当前交付顺序与验收样例)。

依据：[Authoring 架构的 Studio UI](../arch/04_识途Scenario_Authoring与IR详细设计_v1.0.md#13-studio-ui)、[已落地的确定性编写方案](2026-09-13-deterministic-authoring-studio.md)、[前端工作流](../design/front/ai-workflow.md)。本方案按第 11 节审查修订实施；已有确定性编写方案的完成状态不因本次增强而回退。

## 1. 用户结果与范围

用户在同一 Studio 中添加确定性或已支持的 AI 步骤、配置属性、选择前序输出字段、查看编译问题并试跑；修改草稿时仍能查看上一次 Run 的真实结果。手工、录制和未来 AI Authoring 继续汇入同一种 Structured Step，不另造画布数据格式。

本轮交付四项能力：

1. **步骤编辑接入统一**：步骤库、默认值、属性表单与输出说明有明确注册位置。
2. **参数引用统一**：场景输入、前序输出和已声明字段可选择，失效引用可定位。
3. **顺序编辑可持续使用**：插入、重排、删除及最小撤销；保存、冲突、后台刷新不会静默丢失修改。
4. **编译与试跑留在工作区**：诊断可定位字段，试跑结果按冻结快照展示，步骤、Attempt 与 Evidence 对应。

三类 AI 的业务契约、具体指令 / Output Schema 表单和 AI 证据内容由 Midscene 线提供，本方案负责公共编辑能力与页面接入。服务端契约未就绪时先完成现有八种 Step 的增强，不在生产注册表放可运行的假 AI 类型。

本轮不包含自由分支 / 循环 / 并行画布、`@xyflow/react`、通用低代码表单引擎、多语言 DSL、实时协同、多层历史版本树、任意断点续跑。SSE、Live View、受控认证仍归 P7；录制回填归 D2。本轮不增加没有实现的录制、Business Action 或自然语言生成按钮；认可原型里的「AI 辅助」入口属 P16，不在本方案出现。

静态核对发现的具体问题随相关工作修复：

- 引用候选当前包含全部步骤输出，允许用户先选到后续步骤，再由 Compiler 报前向引用。
- `createBlankStep` 对提取步骤固定生成 `outputKey='extracted'`，连续添加会产生同名输出。
- 草稿查询 revision 变化时直接 `setDocument`，可能覆盖本地未保存编辑；键盘重排也没有与保存中的禁用状态完全统一。
- 切换 Step Type 会直接替换专有输入；诊断以文字列表为主，不能直接聚焦错误字段。
- 试跑立即离开 Studio，结果与正在编辑的草稿缺少清楚的并列上下文。

本次只编写方案，以上是代码核对结果，不是已修复或浏览器验收通过的声明。

## 3. 与 Midscene 的契约和修改归属

并行是按修改归属分工；共享契约先由一个集成人提交，消费者不各自实现一份语义。

| 内容 | 修改归属 | 另一条线如何使用 |
| --- | --- | --- |
| 三类 AI Step、Output Schema、固定副作用语义、Executor 版本 | Midscene / 公共契约负责人 | Studio 导入 `@cairn/shared` 类型及 Zod Schema |
| `from` / `fromField`、输出形状描述、Compiler 与 Runtime 引用检查 | 公共契约负责人，随 Midscene 接入交付 | Studio 显示与选择；不另写路径解析或隐式转换规则 |
| AI 启用能力、执行权限、服务端发布 / 试跑检查 | Midscene 控制面 | Studio 读取最小能力响应与现有 RBAC 状态 |
| 页面内步骤注册、属性框架、绑定选择器、草稿状态、诊断导航 | Studio | Midscene 专用表单遵守同一 Props，交给 Studio 注册 |
| AI 专用字段组件、AI 判断 / 用量证据展示组件 | Midscene，分别使用独立文件 | Studio 负责挂载及共用组件接线；两边不同时编辑 `step-editor.tsx` 或 `evidence-viewer.tsx` |
| Run / Snapshot / Evidence Schema、Engine、Session、数据库与迁移 | Midscene / 对应运行时负责人 | Studio 只经 GET / POST 消费，不直接访问 Worker 或数据库 |
| 持久事件、通知、SSE 与 Live View | P7 | 将来更新同一 Query 缓存及查看区域，不要求 Studio 重写 |

新增 UI 注册表只放在 Web 内；运行时 Executor Registry 仍属于 Worker。二者共同引用 Step Type，但不合并成同时携带 React 与执行代码的注册表。改文件前按这张表确认归属，公共 Schema、API DTO 和迁移的修改串行合入。

### 最小共同契约

- **Step 输入输出**：沿用 Midscene 方案第 3 节；`from` 保留根键，`fromField` 首版只选择一个对象自有字段。输出描述从共享契约取得；无法静态判断的输出标为“运行时确定”，不根据示例值猜类型。
- **`fromField` 消费范围**：首版只有 `echo`、`fill` 出现字段选择，与 Midscene 第 3 节一致。`fromField` 仅在已选 `from` 且来源有静态对象形状时出现。场景输入无静态类型：只标“运行时检查”，不提供字段点选，也不阻断合法根键。旧快照无 `fromField`、对象仍 `JSON.stringify` 的兼容规则归公共契约，UI 不复制、不自行序列化对象作为新的字段绑定结果。
- **诊断定位**：复用 `CompileDiagnostic` 的 `stepId`、`inputKey`，增可选 `fieldPath`（相对对应 Step / 场景输入的字符串或非负整数段数组）。Zod issue path 可规范化到此字段；未提供时定位到步骤 / 场景诊断区域，不解析中文 message 猜控件。
- **能力读取**：新增 `GET /scenarios/capabilities`，由 Midscene 控制面提供经过 Runtime Schema 校验的 `executableStepTypes` 与 `unavailableReasons[{type, code, message}]`。接口表示**部署配置与已开放类型**，不是某个 Scenario 的状态，也不代表当前 Worker 健康或任务一定成功。仅返回已开放能力和非秘密原因，不返回模型地址、凭据或 SDK 参数；沿用 `workflow:read` 鉴权，静态路径必须注册在 `:scenarioId` 之前，避免 `capabilities` 被当成场景 id。
- **能力含义**：用户权限另用现有 RBAC 判断；实际发布 / 创建 Run 在服务端重新校验，不信任前端传回的能力清单。新增能力接口、字段定位和输出描述由公共契约负责人实现，Studio 不绕过该依赖直接定义替代协议。
- **保存、发布与调用**：能力未开放与缺少 `ai:execute` 不是同一件事，主操作按第 4 节表格区分。步骤库与类型切换仅允许选择已开放类型，未开放类型可展示禁用原因；既有、符合 Schema 的 AI 草稿仍可编辑和保存。未知 Step 类型按现有 Schema **拒绝加载整份草稿**并提示版本不兼容，不静默删除，也不做未知类型 stub。这是 Web 与 `@cairn/shared` 必须同发的部署约束。
- **AI 锁定字段**（ST04 挂载后，控件只读并说明原因）：`ai_action` 的 `effectType` 固定 `SIDE_EFFECT`，`retryLimit` 固定 `0`；`ai_extract` / `ai_assert` 固定 `READ_ONLY`。AI Assert 的 `passed: false` 不是可改重试。不允许把 AI 意图改成确定性动作来“自动获得重试”。

本方案不新增数据库表，也不修改快照或摘要算法。公共契约在 Midscene 线中增加的字段和兼容规则由该线负责；本方案保留旧字段缺省的显示回退，不把缺失值伪造成已验证结果。

## 4. 交互布局与组件复用

**主要任务**：创建、修改、验证一条绑定 Target 的有序场景。页面保留 Target、已发布版本、草稿 revision 和未保存状态，明确用户当前在编辑什么。

```text
Target / 已发布版本 / 草稿状态                       保存 / 试跑 / 发布
┌───────────┬───────────────────┬─────────────────────┐
│ 步骤库     │ 有序步骤           │ 当前步骤属性         │
│ 确定性     │ 01 打开页面        │ 名称 / 业务输入      │
│ AI        │ 02 AI 提取订单     │ 参数来源 / 输出字段  │
│ 调试夹具   │ 03 填写查询条件    │ 字段错误 / 执行策略  │
└───────────┴───────────────────┴─────────────────────┘
场景输入与编译诊断
试跑摘要（可折叠）：状态 / 冻结版本 / 当前历史步 Attempt
```

沿用认可的 [Studio 视觉参考](../front_design/2026-09-13-foundation-lab/index.html#studio)、`Main`、`PageHeader`、现有 shadcn / Radix 控件与 Design Token。产品目标是左库 / 中序 / 右属性 / 下试跑摘要；**ST02 不必先做持久左栏**。现有八种类型继续用“添加步骤”菜单即可，持久步骤库留给 ST04（或单独布局提交），主要服务 AI 分组与禁用原因，避免和草稿保护抢同一批改动。

空间不足时步骤库（若已出现）收为“添加步骤”弹层，优先保障序列和属性可读。窄屏按步骤 / 属性分区切换，保留返回当前步骤的入口，不把桌面三栏整体缩小。断点对齐认可原型：约 1660 / 1220 / 1020 / 740；验收另覆盖 1366 / 1440 / 1920 与一个更窄视口，不出现页面横向溢出。

本轮用 CSS Grid / Flex 组合，不增加分割窗布局库或虚拟列表。沿用最多 32 步的契约，不提前建设无限节点画布。AI 仅在类型入口和能力标识使用紫色；蓝色表示操作，运行成功 / 失败仍用统一状态色，并辅以文字。

### 主操作

| 状态 | 最高强调动作 | 其他动作 |
| --- | --- | --- |
| 存在本地修改（含未合法的字段草稿） | 保存草稿 | 试跑 / 发布说明需要先保存；字段非法时保存也显示明确原因 |
| 已保存、可执行且具备 `run:execute`（含 AI 步时还要 `ai:execute`） | 试跑 | 发布和运行已发布版本保持次要操作 |
| 已保存但编译阻断，或部署未开放草稿中的 AI 类型 | 定位并修复问题 | 不显示可执行的假成功入口；已有合法草稿仍可编辑保存；发布与试跑由服务端阻断 |
| 已保存、类型已开放，但用户无 `ai:execute` | 发布仍可用（不剥夺 workflow 发布） | 试跑 / 正式 Run 阻断，说明缺 AI 执行权限 |
| 无 `run:execute` | 可保存；发布按原 workflow 规则 | 试跑 / 正式 Run 阻断 |
| 只读用户 | 无写入主操作 | 可以阅读有权限访问的定义及运行证据 |

能力未开放与缺少 `ai:execute` 必须在操作区用不同原因说明。前端隐藏不是安全边界；服务端仍拒绝绕过。按钮禁用原因在操作区可读，不仅藏在 Tooltip。加载时保持尺寸和动作名称，阻止重复提交；保存中的鼠标、快捷键与字段输入遵守同一个禁用条件。

## 5. 步骤编辑注册与顺序操作

在 `features/scenarios` 内建立一份静态编辑注册表，按 Step Type 组织 `label`、分组、简短说明、默认 Step 构造及专用字段组件。`blank-step.ts` 和类型标签向这份表收拢，现有定位、断言、策略控件继续复用。shared 的 Step Schema 是验证来源，注册表不能自定另一个必填字段或副作用契约。

**ST02 起，步骤库与改类型不得再 `EXECUTABLE_STEP_TYPES.map`。** 能力接口未就绪时使用显式八种允许列表（`navigate` / `click` / `fill` / `extract` / `assert` / `echo` / `delay` / `fail`）。ST01 合入前，生产下拉不出现 `ai_*`。能力响应就绪后改为读 `executableStepTypes`，未开放类型只展示禁用原因。当前代码直接遍历枚举；Midscene 一旦把 AI 类型写入该常量，没有闸门就会全局开放，本条就是为挡住这条时序。

普通 Web 步骤、AI 步骤、调试夹具分别分组；`echo` / `delay` / `fail` 仍可使用，但调试组默认折叠。表单按 Step Type 显式提供，避免把所有 Zod Schema 反射为通用表单。历史 Run 的类型标签保留未知类型字符串回退，展示层不能为了查标签而加载整个编辑器。

- **添加**：无选中项时追加末尾；选中步骤时可以在其后插入。生成新的 Step ID；默认输出名在场景输入及现有输出中去重。已有输出名不被批量改写。
- **选择**：用稳定 Step ID 标识，重排后仍保持同一选中步骤；步骤名称、类型、输出摘要、错误标识直接可见。
- **重排**：复用上移 / 下移和键盘操作，移动后立即重做引用校验。边界操作禁用。快捷键必须检查 `event.target`，输入框、弹层内不拦截会与文本或控件操作冲突的快捷键，并与保存中的 `disabled` 共用同一条件。拖拽不作为本轮交付条件。
- **删除**：沿用确认弹层，列出以 `from` 或 `fromField` 引用该输出的后续步骤；不级联删除消费方，不自动改成字面量。删除后保留失效引用及诊断；仍遵守场景最少一步的现有契约。
- **改类型**：会重置专有字段时先说明影响并确认；保留 Step ID 和名称，专有输入按新类型重新构造，失效输出引用留给诊断处理。不把 AI 意图自动转换为确定性动作，也不允许借改类型绕过第 3 节的锁定字段以获得重试。
- **撤销**：提供最近一次结构操作（插入 / 重排 / 删除 / 改类型）的一级撤销，同时恢复选中项。下一次**结构操作**、保存成功、重载或切换场景使该撤销失效。纯文本 / 属性输入保留原生撤销，**不清**结构撤销。不新增全局历史引擎。

新增步骤、重排、删除及撤销直接更新同一份提交候选；改属性先写入字段草稿，Zod 通过后再写入提交候选（见第 7 节）。不在步骤库、属性面板各保存一份可独立修改的 Step。

## 6. 参数绑定与字段诊断

输入来源分为“直接填写”“场景输入”“前序步骤输出”。候选来自 `inputs` 与当前步骤之前的 `outputKey`，不列出自己和后序步骤。首版只有 `echo`、`fill` 在已选 `from` 且来源有静态对象形状时再选其已声明字段；示例“AI 提取订单 → orderNo”保存为共享契约的 `from` / `fromField`，不把显示文字拼成表达式。其他 Step 类型不出现 `fromField` 控件。

既有未声明、被删除或重排后失效的引用原样显示并标错，不因为它不在候选列表就清空。来源改名、字段删除和类型改变后，保留原引用并展示受影响步骤；不按相似名称猜测替换。

绑定选择器复用共享输出描述和编译规则：

- 有静态 Schema 的字段显示类型、必填情况与兼容性；已知不兼容的字段不可新选，原因可读。
- 无静态类型的场景输入 / 既有输出标明需要运行时检查；不提供字段点选，不把“未知”当作兼容通过，也不以此阻断原有合法根键引用。
- `fill` / `echo` 新字段绑定的标量转换、对象拒绝和保留属性名规则完全使用 Midscene / 公共契约定义。UI 不自行 `JSON.stringify` 对象作为新的字段绑定结果。
- 字面量与引用互斥；清除字段引用后不能残留一个无来源的 `fromField`。

校验分两步，且不得把半截 Step 放宽进 `stepSchema`：

1. 先用现有 Zod Schema 校验提交候选。文档尚未合法时只显示表单错误，**不调用** `compileScenarioDocument`。
2. 候选合法后再调用同一 Compiler 做语义检查。编辑态诊断继续使用 `mode: 'release'`，与今天 Web 本地编译一致；服务端保存仍走现有 `save` 口径（未声明 `from` 只是 warning）。不要为了输入过程把保存期改成 error。

表单输入过程可以暂时不合法，临时文本留在第 7 节的字段草稿里；切换步骤、重排、未保存离开都不得丢失或悄悄回退为旧值。保存前阻止无法形成合法文档的输入，并定位第一个错误。

步骤卡显示诊断数量，字段下显示具体原因；页面保留可聚焦的诊断摘要。点击摘要先选择相应 Step，再聚焦对应字段；没有 `fieldPath` 时定位步骤诊断区。实时输入不反复抢焦点，显式提交失败时才引导到错误。使用可见标签、`aria-invalid`、`aria-describedby` 和必要的反馈播报，不仅改变边框颜色。

本地已知字段错误及时显示；Target 状态、能力和权限未知时不猜成已启用。发布和试跑以服务端检查为准，并将返回的定位信息显示回原草稿。

## 7. 草稿状态与保存边界

编辑状态保留在当前 Studio 内，沿用 React 局部状态；可提取一个本功能使用的 hook / reducer 收口操作，不新建跨页面全局编辑 Store。本地编辑拆成三层，禁止再发明第二套可持久化文档：

| 层 | 内容 | 规则 |
| --- | --- | --- |
| 基线 | 服务端 `revision` + 合法 `ScenarioDocument` | 首次打开或切换 Scenario 时初始化；保存成功后只接受本次提交确认再替换 |
| 提交候选 | 上一份 Zod 通过的 `ScenarioDocument` | 仅在 Zod 通过时更新；保存 / 发布 / 试跑只发送这一份。不把半截 Step 写入 `stepSchema` |
| 字段草稿 | 按 `stepId` 或场景输入键保存尚未合法的原文（空 URL、半截 `outputKey` 等） | 切步骤、重排、未保存离开都保留；不进入 Scenario Definition |

另需区分：当前选中项、结构操作撤销、保存请求与冲突状态。`dirty` 以「字段草稿非空，或提交候选相对基线有差异」为准。文档尚未合法时只显示表单错误，不调用 Compiler。

TanStack Query 管服务端数据，不能把每次查询响应直接覆盖本地文档：

- 首次打开或切换 Scenario 时初始化；没有本地修改时可以接受更新后的服务端基线。
- 有本地修改时，后台查询发现 revision 改变只提示“服务端草稿已更新”，保留编辑与原基线 revision，不自动合并或覆盖。
- 保存始终发送本地编辑所依据的 revision 与提交候选。成功后只接受本次提交的确认结果，再更新 Query 缓存和基线，并清空已提交成功的字段草稿；失败保留输入。
- 保存、发布、试跑三处遇到 `SCENARIO_DRAFT_CONFLICT`（409，正文可带当前 `revision` 与服务端文档）都保留本地修改，提供明确的重载操作；用户确认放弃本地编辑后才接收服务端草稿。不给“强制覆盖”绕过 OCC 的入口。今天只有保存认这个码，发布和试跑同样会 409，必须同一套处理。
- 有本地修改或不合法的字段草稿时，离开场景使用现有路由能力和浏览器离页提示保护；留在当前页继续修正。首版不把可能含敏感输入的草稿自动写入 localStorage，也不承诺崩溃后的本地恢复。

继续使用原有保存 / 发布接口：保存不发布，发布不修改已有版本，试跑只执行已保存且通过编译的草稿。撤销本地结构操作不会撤销已经发布的版本或已经创建的 Run。

## 8. 试跑与 Evidence 接入

`TrialDialog` 保留目标账号、运行输入及创建请求，成功后通过回调交回 Run，由 Studio 写入同一 `['runs', runId]` Query 缓存并打开**可折叠试跑摘要**，保留“打开完整运行详情”。试跑 HTTP 已支持可选 `idempotencyKey`，本轮只补客户端：只有显式创建动作发起 POST；同一次提交及网络重试复用一个幂等键，修改输入后重新试跑使用新键。不必新接口。

场景路由增加经 Schema 验证的 `runId` 查询参数，用 **replace** 写入当前场景 search，不离开 Studio、不新建独立详情路由。再次试跑替换 `runId`。刷新可重新查询该 Run；不为了恢复界面自动再创建 Run。展示前核对 `run.scenarioId` 与当前场景一致，并遵守 `run:read` 权限；不匹配、403、404 只影响结果区域，不清空正在编辑的草稿。

工作区试跑区按认可原型做成**一条摘要 + 当前历史步结果**，不把 Run Detail 整页嵌进三栏 Studio：

- 默认展示：Run 状态、冻结的 `scenarioVersionId` / `scenarioVersionKind`、开始时间、证据完整性，以及当前选中历史步的最新 Attempt 摘要（输入 / 输出 / 判断 / 错误 / 一张截图）。有对应版本元数据时补充展示，不将当前草稿 revision 冒充为历史 Run 的来源。
- 完整 Attempt 列表、Trace 与授权下载走“打开完整运行详情”。失败和证据缺失在摘要里保持直接可达；Step 尚未开始的运行级错误也要显示。
- 试跑区可折叠，避免压住序列和属性。
- 运行定义与草稿编辑分别选中。点击运行步骤可定位当前草稿相同 Step ID；该步骤已经删除时继续显示历史步骤，并说明当前草稿没有对应项，不能按 ordinal 错配另一条步骤。
- 同一个 Step ID 的草稿内容已经改变时，历史输入、输出及判断仍按 Snapshot 展示，不在新属性上直接贴一个旧“成功”标识。当前编辑不改变已创建的 Run。
- 运行结果按真正的状态区分失败、取消、等待认证和待核查。取消提交成功只说明请求已受理，实际终态由查询响应确认；认证处理和核查仍链接既有处置入口。

结果读取复用 `fetchRun`、`fetchRunEvidence` 和现有 Query 键。无 SSE 时：创建成功后至少主动 GET 一次，展示最近获取时间，并提供手动刷新；不新增自动高频轮询，否则 queued Run 会看起来像失败。P7 后续更新同一缓存即可；本轮不实现 SSE 通道、画面推流或人工输入协议，也不展示假浏览器画面。

## 11. 审查修订（2026-09-13）

对照现有 Studio / Compiler / 试跑 API 审查后，方案有条件通过。本节是写入正文的约束摘要，不改 D0–D4 顺序，也不当作已经实施。

1. **三层本地编辑**：基线 / 提交候选 / 字段草稿。非法时不调 Compiler；`dirty` 含字段草稿；不放宽 `stepSchema`。
2. **枚举时序**：ST02 起禁止遍历 `EXECUTABLE_STEP_TYPES`；能力未就绪只暴露八种类型；Web 与 `@cairn/shared` 同发；未知类型拒绝整份草稿，不做 stub。
3. **`fromField`**：仅 `echo` / `fill`；仅在已选 `from` 且来源有静态对象形状时出现；场景输入不提供字段点选。
4. **AI 锁定字段**：`ai_action` 固定副作用且 `retryLimit = 0`；Extract / Assert 固定只读；不能改成确定性步骤来获得重试。
5. **试跑区**：可折叠摘要 + 创建后至少 GET 一次 + 手动刷新；`runId` 用 replace 写入 search；不嵌整页 Run Detail。
6. **OCC**：保存 / 发布 / 试跑三处 409 同一套处理，无强制覆盖。
7. **能力 ≠ 权限**：部署未开放阻断发布与试跑；类型已开放但无 `ai:execute` 仍可发布、不可试跑 / 正式 Run。
8. **收紧但不改范围**：持久步骤库移出 ST02；结构撤销不被文本输入清掉；编辑态诊断继续 `release`，保存仍走 `save`；键盘检查 `event.target`；断点对齐认可原型；原型「AI 辅助」不做。

ST01 仍等与 Midscene 共同评审后由一个集成人串行合入。未合入前禁止本地伪造生产 DTO。
