# 浏览器仿真 AI 与平台通用 AI：独立模型配置边界

日期：2026-09-13。状态：**需求边界已记录，未实施；具体功能与实现方案待定**。

本文补充两类 AI 能力及模型配置的边界，不是完整 P8 / P9 开发方案。对应[工程计划 P8](../plan/识途开发路线与工程实施计划.md#p8-最小模型路由与-provider-适配)；交付顺序只维护在该计划第 5 节。

## 1. 两类能力分别配置

| 配置域 | 服务的能力 | 依赖边界 |
| --- | --- | --- |
| 浏览器仿真 AI | 当前以 Midscene 视觉理解、定位与操作为主，服务于正式 AI 浏览器步骤 | 由浏览器 AI 适配层读取，经显式配置传给 SDK；受统一 Run、Browser Runtime 与 Evidence 管理 |
| 平台通用 AI | 平台自身的生成、分析与辅助判断能力；辅助生成脚本／步骤、判断建议是候选用途，尚未确定首批功能 | 平台直接调用模型服务，独立选择模型；不依赖 Midscene、page-agent 或 Browser Session |

平台通用 AI 是需要建设的能力。P16 已描述 AI 辅助编写，但不能以此认为模型配置已经具备，也不能把平台 AI 配置隐藏在 Midscene 的配置里。

page-agent 属于浏览器 Agent 候选，不代表平台通用 AI。是否接入以及使用什么模型仍按浏览器能力需求决定。

当前 [`.env.example`](../../.env.example) 的 `CAIRN_S06_MODEL_*` 只服务于 S06 探针，不是上述任一配置域的正式实现；填入这些值不能启用平台通用 AI。

## 2. 配置独立，基础设施按需复用

两类能力分别管理启用状态、模型服务地址、模型名称、凭据引用、超时及调用预算。模型能力和参数按实际用途校验；Midscene 所需的模型家族等 SDK 参数只属于浏览器适配层。

- 调整一类能力的模型、凭据或参数，不得隐式改变另一类能力的配置。
- 一类配置缺失或不可用，只影响依赖该配置的功能；不得静默回退到另一类配置。两类 AI 均未启用时，确定性功能仍可使用。
- 两类配置可以显式选择同一家供应商、同一个模型或同一凭据引用；共享凭据时，供应商配额与密钥失效仍可能同时影响两类调用，不承诺资源故障隔离。
- 可复用 OpenAI 兼容客户端、SecretProvider、日志、超时取消与用量记录。平台通用 AI 的调用不经过 Midscene SDK；不为配置分开而复制两套调用基础设施或部署两个网关。

平台通用 AI 以 OpenAI 兼容接口为接入基线，需求包括 DeepSeek 和千问。具体模型及文本、结构化输出、工具调用等能力随首个功能确定并验收；不能以接口格式兼容推定所有能力兼容，也不能以接通一条 Midscene 视觉模型路线宣称两家供应商的平台 AI 能力已经完成。

环境模板与本机／远程画像先加入两类 AI 的配置规划注释，不新增没有读取方的环境变量。正式变量名、加载位置、Schema 和部署说明随实现方案确定，与读取方和模型调用一起落地，并保持两个配置域可独立配置。

## 3. 功能语义与运行边界

平台 AI 调用按功能关联请求、操作者、实际模型、配置版本、提示版本、耗时、用量及错误；凭据通过 SecretProvider 获取，不进入前端、页面脚本、普通日志或业务快照。

辅助生成和分析不要求创建浏览器 Session，也不为了调用模型而伪造 Run / Attempt。生成结果是可审查的建议或草稿，不自动发布或执行；涉及 Scenario 的产物仍须符合版本化 Structured Step、校验与编译要求。

“AI 辅助判断”需要在具体功能方案中说明判断对象和结果用途。若只是对材料或结果提供建议，使用平台 AI 调用；若作为 Scenario 中决定运行结果的 AI Assert，则仍进入统一 StepRun / Attempt、输出契约和 Evidence，按该 Run 的冻结配置执行。不能因为使用平台模型就绕过 Runtime，也不能把所有判断都绑定到 Midscene 的同名方法。

## 4. 实现时的验收边界

1. 两类配置设置为不同服务和模型时，各调用到自己的配置；修改其中一类不改变另一类，也不改变已启动 Run 的解释。
2. 平台通用 AI 在未启用 Midscene、未创建浏览器 Session 时仍可独立验证模型调用。
3. 未启用的配置不阻断平台启动；启用的配置经过 Runtime Schema 校验，缺失或非法值有明确诊断；不使用另一类配置补齐。
4. 两类调用分别记录用途、配置与用量，统一执行授权、超时取消、预算和脱敏要求；Run 内调用保留完整的执行关联。
5. 平台 AI 实施时，对首批功能实际使用的 DeepSeek、千问模型分别验证调用与输出契约；浏览器 AI 另验视觉与动作能力。离线契约测试不能代替真实模型验收。

## 5. 尚未确定的范围

首批平台 AI 功能、脚本生成的具体产物、判断条件和界面入口尚未确定。完整模型管理页面、自动选模、多供应商自动回退和独立网关均不是本次需求的前置。

后续模块开发方案须引用本边界，并明确实际调用方、配置契约和验收样例后再实施；本记录不代表已经承诺交付上述候选功能。
