# 识途录制器：步骤纠错、录制上下文与真实浏览器验收

日期：2026-09-13。状态：**已交付**。D2 已拍板：插件只做删除，重排与改值留给控制台顺序编辑。
范围：接管修好之后剩下的三个体验缺口——录错一步只能整段重录、看不出正在录哪个页面、步骤和页面之间不能互指；以及把这次抓出三个 bug 的真实 Chrome 探针固化成可重复的验收脚本。

前置：[工作台收敛与设计语言对齐](2026-09-13-extension-workbench-ui.md)（登录门禁、步骤列表、侧栏接管边界）、[控制台登录与录制上传](2026-09-13-extension-login-and-recording-upload.md)（JSONL → IR 草稿的上传契约）。采集内核与上传契约本期都不改。

## 1. 为什么现在做

面板接管修好之后，实测剩下的问题不是「少个按钮」，而是三件事让人不敢用：

1. **录错一步只能整段清空重录。** 真实录制一定会录进多余点击（点错、点开又关、误触）。面板此刻唯一的编辑能力是「清空」，噪音只能带着上传，推给控制台去删。这是「体验差」里最重的一条。
2. **看不出正在录哪个页面。** 面板只说「正在录制当前标签页」。用户切了标签、开了新窗口，就不知道录的是哪一页，也不知道为什么没录到。
3. **步骤和页面之间不能互指。** 步骤现在能读懂（`button「查询」`），但不能"指给我看是哪个按钮"。核对只能靠脑补。

## 2. 目标与非目标

### 目标

1. 能删掉误录的某一步，并且能撤销这次删除。
2. 面板明确写出正在录哪个页面（标题 + 地址），未挂接时明确说没挂。
3. 鼠标停在某一步上，被录页面里对应元素高亮。
4. 真实 Chrome 里的登录、挂接、录制、展开、删除有一个可重复跑的脚本，不再靠"构建通过"当验收。

### 非目标

- 不改采集内核，不 fork vendor Recorder。
- 不做拖拽、不做断言录制、不做草稿回填、不做 AI 步骤说明。
- 不在插件里编辑平台定位候选（`TargetDescriptor`），那是控制台的事。
- 不把这个脚本做成默认 CI 门槛（需要 headed Chrome 与本地 API）。

## 3. 决策

### D1. 删除是「上传前排除」，不是改采集事实

硬禁区要求 Recorder 内部格式不能成为 Runtime 唯一事实源，同样地，面板也不该反过来篡改引擎已经采到的东西。所以删除的语义是：

> 引擎采到的 JSONL 一行不动；面板维护一个**排除集**，上传时只把保留下来的行拼成 `events`。

| 项 | 决定 |
| --- | --- |
| 排除粒度 | 按步骤卡（IR item）删，落到该 item 的 `sourceIndexes` 对应的原始 JSONL 行 |
| 排除集的标识 | 原始 JSONL 行的下标。录制是追加式的，已有行的下标不变；item 的 `index` 会因删除重排，**不能**用它当标识 |
| 删除后如何重新出列表 | 先 `extractRecordingEvents(sources)`，剔掉排除集，再 `normalizeRecording`。不能只在 UI 里隐藏——连续 `fill` 合并、`about:blank` 丢弃等归一化会随之变化 |
| 撤销 | 记住最近一次删除的下标集合，状态行给「撤销」。刷新面板不保留撤销历史 |
| 幂等 | 删除改变了上传指纹，现有逻辑会换新的 `recordingId`，等于新一段草稿，不与已上传的那份冲突 |
| 敏感值 | 删除不会让被剥掉的敏感值回来；排除只做减法 |
| 清空 | 保留。清空是「这段不要了」，删除是「这一步不要了」，两者都需要 |

删除要确认吗：不弹窗，删完在状态行给「已删除第 N 步 · 撤销」。窄栏里弹窗成本太高，而撤销比确认更符合"手滑"这个真实场景。

### D2. 重排与改值不在插件做（已拍板）

[确定性场景编写](2026-09-13-deterministic-authoring-studio.md) 已经把 **增删、上移下移、键盘重排、参数绑定、类型化表单** 定在控制台顺序编辑里，录制回填（`D2 录制回填`）会把 IR item 映射进同一个 `ScenarioDocument`。如果插件也做重排和改值：

- 同一批事实会有两个编辑面，两边的校验、诊断、撤销语义都要各写一遍；
- 380px 侧栏里做值编辑和重排，交互天然比控制台差，用户还是会回控制台重做；
- 重排录制步骤的语义比看起来危险：导航顺序、`pageAlias` 页面交接、`fill` 与 `click` 的先后都可能被排到不成立的状态，而插件此刻没有 Compiler 校验。

所以分工定为：**插件负责"把录脏的部分去掉"，控制台负责"把留下的部分编排好"。** 删除属于采集现场的纠错，重排和改值属于编排。以后要改判，也要连同录制回填一起改，不单独在插件开第二个编辑面。

### D3. 录制上下文：说清在录哪一页，并能指给用户看

**在录哪一页。** 顶栏状态行补一行：被录标签页的标题与地址；未挂接时写「未挂接，点开始录制会挂到当前标签页」。数据来自 background 已有的 `attachedTabIds`，新增一个查询消息返回 `{ title, url, mode }`。

拉取时机：面板挂载、`mode` 变化、`sources` 变化时各拉一次。这三个都是推过来的事件，不是定时器——不允许用高频轮询顶替。

**指给用户看。** 鼠标停在某一步（或键盘聚焦到该步）时，向引擎 `dispatch({ event: 'highlightRequested', params: { selector } })`，被录页面高亮对应元素；移开时用空 selector 取消。

| 项 | 决定 |
| --- | --- |
| selector 来源 | 原始 JSONL 行的 `selector`（`extractRecordingEvents(...)[sourceIndexes[0]]`），不是 IR 的定位候选 |
| 何时不发 | 未挂接、该步没有 selector（如 `navigate`）、被排除的步 |
| 与「选取」的关系 | 选取是从页面找元素，高亮是从步骤找元素，两个方向，都保留 |
| 是否进入代码视图 | 不进。高亮只是高亮，不打开编辑器 |

### D4. 真实浏览器验收固化

这次三个 bug 全部只在真实 Chrome + 真实侧栏下暴露，`vitest` 和 `vite build` 一个都拦不住。固化成仓库内脚本：

```text
packages/extension/playwright-crx/probe/panel-flow.mjs
```

用 worker 已依赖的 Playwright（扩展包不为一个本地探针加运行时依赖），`launchPersistentContext` 加载 `dist/`，覆盖 15 项：

1. 未登录时经面板同一条消息通道点挂接 → 回「请先登录识途」，页面没被接管；
2. 真实账号登录 → 目标系统下拉拉到列表；未挂接时状态行说清会挂当前标签页；
3. 面板里点「开始录制」→ 挂接完成、按钮变「停止录制」，重载后已选目标系统仍在；
4. 在被录页面上做真实操作 → 步骤出现、定位摘要能区分同名操作、状态行写出正在录哪一页；
5. 展开某一步 → 字段与控制台草稿详情同名（`sourceAction` / `candidateStepType` / `input`）；
6. 删除某一步 → 列表少一条、状态行有撤销出口、撤销能放回来；
7. 退出 → 回登录页，且扩展自己不再认为有页面被接管。

跑法：`pnpm build` 后 `pnpm probe:panel`；API 地址与账号用 `CAIRN_PROBE_API` / `CAIRN_PROBE_EMAIL` / `CAIRN_PROBE_PASSWORD` 覆盖。全过退出码 0，失败退出码 1 并逐条打印。

边界写死：

- 需要本地 API 与 headed Chrome，**不进默认 CI**；作为改录制器时的必跑脚本，包 README 写清跑法。
- 脚本不造假：会话必须来自真实登录接口，步骤必须来自真实录制，不允许往 storage 里塞假步骤当通过。
- 被录页面是脚本内置的本地夹具，不打外部站点，探针不依赖任何手工起的服务。
- 侧栏本身不能被自动化打开（`sidePanel.open()` 需要用户手势），脚本用扩展页标签顶替侧栏，用重载那一页顶替真实侧栏「换路径 → 重载 → 重连」里的重连；侧栏接管时序另由 `src/cairn/__tests__/attach-panel.test.ts` 回归。
- 不能用 `chrome.debugger.getTargets()` 判断接管：被录页面本来就挂着 Playwright 自己的调试连接，要问扩展的状态消息。

## 4. 界面结构

```text
识途录制器                        Administrator  退出
目标系统  [ 智慧运维管理平台 ▾ ]
[ 上传到平台 ]

[ 停止录制 ]  [ 选取 ]                     清空

● 正在录制：订单管理 · lab.example/orders
  已记录 4 步

1  打开 lab.example/orders                展开  删除
   已映射 · navigate
2  填写                                   展开  删除
   textbox「订单号」
   已映射 · fill
3  点击                                   展开  删除
   button「查询」
   已映射 · click
```

删除后状态行：「已删除第 3 步 · 撤销」。悬停某步时该步高亮，同时页面上元素高亮。

## 5. 落地边界

| 改 | 不改 |
| --- | --- |
| `src/cairn/`：排除集与预览、删除 / 撤销、上下文行、悬停高亮 | `playwright-crx` 采集、`getActions()`、vendor Recorder |
| `background.ts`：新增被录标签页状态查询 | 上传契约、`normalizeRecording`、草稿表、控制台草稿页 |
| `probe/panel-flow.mjs` 与包 README 的跑法 | 默认 CI 门槛、`turbo` 任务图 |

`normalizeRecording` 留在 shared 不动：排除发生在它之前，它继续只管"给定 events 怎么归一"。

## 6. 验收

1. 录 5 步，删掉中间一步：列表剩 4 步、编号连续，上传包里没有被删那一步。
2. 删完点撤销：那一步回到原位，编号恢复。
3. 删掉与前一步同目标的 `fill`：剩下的步骤按新的合并结果重新出列表，不是简单隐藏。
4. 删到只剩空页面打开：上传禁用并说明"没有可保存的业务操作"。
5. 敏感填写被删后撤销：值仍然是被剥掉的状态，不因删除回流明文。
6. 面板写出正在录的页面标题与地址；换标签重挂后这行跟着变；未挂接时写明未挂接。
7. 鼠标停在某步，被录页面对应元素高亮；移开取消；`navigate` 步不发高亮也不报错。
8. 上下文与高亮全程没有定时轮询（代码里没有 `setInterval` / 定时 `fetch`）。
9. `pnpm probe:panel` 在本地 API + Chrome 下 15 项全过，失败时逐条输出足以定位的现场。

## 7. 现在不做

拖拽重排、值编辑（除非 D2 改判）、断言录制、草稿回填、AI 步骤说明、把探针接进默认 CI、在插件里编辑定位候选。
