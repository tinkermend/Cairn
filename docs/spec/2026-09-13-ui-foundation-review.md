# UI 底座交互评审原型

日期：2026-09-13。状态：交互原型的设计方向已获用户认可；已补 AI 开发工作流、分档验收 skill 与现有设计检查的 CI 接线。用户进一步批准迁移「目标系统」与「场景」，两类页面的列表 / 详情现已迁为真实 React 样板并完成本地定向验收。

## 目标

验证视觉规则、控件反馈与页面布局是否适合识途的管理、编排和复盘任务。延续现有 React / shadcn / Radix 技术边界，本轮以独立 HTML 原型验证候选设计，不接后端与真实目标系统。

## 交付

[打开交互评审台](../front_design/2026-09-13-foundation-lab/index.html)。

[评审路径与验证记录](../front_design/2026-09-13-foundation-lab/README.md)。

1. 组件交互台：颜色与层次、按钮、表单校验、选择、交互卡片、菜单、弹窗、侧栏、加载、错误与状态反馈。
2. 目标系统管理：筛选、选择详情、新建目标、添加目标账号、空态与加载失败。
3. Scenario Studio：顺序步骤、属性编辑、添加步骤、AI 建议显式接受、保存、模拟试跑。
4. 运行复盘：步骤与 Attempt 关联证据、输出与断言、执行与证据双状态、认证等待、人工核查、断线缓存状态。

## 比较方式

- “当前 Token”直接引用现有 tokens.css；“候选方案”以局部变量覆盖控制外观。两者使用同一套新布局与示例内容，不宣称当前 Token 模式等同于现网页面。
- 可切换标准 / 紧凑密度、收起导航、减少动效。复杂工作区在宽屏分栏，窄屏重排。
- 以同一任务路径比较外观与操作效率；不靠不同业务数据营造差异。

## 领域约束

- Scenario 绑定 Target；控制台成员与 TargetAccount 分开。
- 确定性与 AI Step 同列，只有顺序执行，无自由分支。
- AI 建议显式接受后进入草稿；模拟试跑冻结步骤副本，继续编辑草稿不修改该快照。
- 失败 Attempt 与失败 StepRun 分开；执行成功与证据不完整允许同时显示。
- 待核查的副作用步骤不提供盲目重放或恢复续跑；核查结论只结束该次模拟运行。
- 等待认证指目标账号；样本中没有有效执行租约，不把会话复用画成重新登录。
- 所有交互仅操作浏览器内的示例状态，不访问 API、Worker、目标系统或凭据后端。

## 验收

- 新旧外观切换保持数据；组件可点击、聚焦、校验、加载与报错。
- 原生 dialog 保持键盘操作、Escape 关闭、关闭后焦点返回。
- 输入文案在展示时转义；模拟动作不执行任意用户输入。
- 1366 / 1440 / 1920 与窄屏无页面整体横向溢出，必要表格可以在容器内滚动。
- 带步骤的样本保持有序状态，Run / Attempt / Evidence 关系正确。
- 使用项目现有 Playwright 留下一份可重复执行的交互与布局检查。

## 后续收敛

用户已认可当前原型效果。后续选管理页和工作区各一页做真实组件试点，再把验证结果更新到 docs/design/front 的 Token、组件状态、页面布局与实现索引。将验收后的页面作为 AI 开发范例，不引入新的 UI 框架或通用页面生成器。

## 正式接入方案

设计认可覆盖色彩关系、表面层次、控件反馈和任务分栏方向。生产接入以真实组件、接口、中文内容和可访问性验证为准，不把原型的每个像素或模拟逻辑定为不变量。

下面是 UI 迁移内部的工作范围；全局开发顺序仍以[工程实施计划](../plan/识途开发路线与工程实施计划.md#5-当前交付顺序与验收样例)为准。

### 第一批：共用规则与组件

- 对照认可原型演进 `docs/design/front/tokens.css`，继续由 Web 主题直接导入；候选数值需通过对比度与层次检查，不维持两套生产 Token。
- 沿用 `components/ui/` 的 Button、Input、Select、Badge、Card、Alert、Dialog、Sheet；补齐本次样板需要的变体和状态，不重写 Radix 行为层。
- 围绕已有 `Main` / `PageHeader` 调整管理页与工作区组合；复用 Sidebar 的折叠能力。只有出现真实复用时才新增轻量布局组件。
- 正式页面使用当前字体刻度。Loading、焦点、Disabled、错误保留输入和减少动效需要由真实组件验证。

### 第二批：两张真实样板页

| 样板 | 当前代码 | 改造范围 | 能力验收 |
| --- | --- | --- | --- |
| 目标系统管理 | `features/targets/index.tsx`、`detail.tsx` 和现有表单 | 表格筛选、对象详情、目标账号与认证状态的层次；保持真实 CRUD、权限与校验 | 目标与账号分别管理；创建 / 编辑 / 失败 / 无权限路径准确 |
| 场景管理与详情 | `features/scenarios/index.tsx`、`detail.tsx`、`create-dialog.tsx` | 搜索与状态筛选、目标上下文、有序步骤与选中步骤属性；保留现有创建与运行入口 | 顺序和输入输出准确、目标绑定与权限正确、失败保留输入；不把定义状态当成运行结果 |

本次按用户选择以 Target + Scenario 作为两张真实样板，替换此前拟定的 Target + Run。场景详情采用有序步骤工作区，已有创建能力继续使用现有表单；完整 Sequence Editor、AI Authoring 等独立业务能力按各自方案落地。运行复盘原型继续作为后续参考。已有但尚未实现的接口与状态不得用原型模拟结果填充成“功能已完成”。

### 第三批：收敛为默认工程能力

- 验收通过的真实页面成为优先样板；同步现有设计语言、组件规范和实现索引，标清原型与正式实现状态。
- 使用固定、无秘密信息的测试数据验证公共组件与样板；视觉差异要经过解释，不能只更新截图基线。
- [AI 前端开发工作流](../design/front/ai-workflow.md)约束任务识别、布局选择、复用与交付；[前端验收 skill](../../.agents/skills/shitu-frontend-acceptance/SKILL.md)按轻量 / 局部 / 页面或底座分级。
- `pnpm check:design` 已接入 CI 配置，负责明确规则；真实页面能力与视觉验收按变更范围执行。CI 接线的本地检查与远端 CI 运行结果分别记录。

### 小偏差的纠正方式

同一视觉问题出现在多页时修共用 Token 或组件，局部页面问题修分组与组合，业务状态问题修领域映射。只复测受影响范围。反复出现的同类偏差再补最小自动检查，避免规范与测试无限膨胀。

## 复查与定向迭代记录（2026-09-13）

迁移前复查结论：可以作为后续开发的设计方向与基础约束使用；当时尚不能宣称认可效果已经固化为生产默认能力。后续迁移结果见本文末尾。规范、可执行检查、真实组件与 skill 分档执行需要分别验证。

### 已验证并修正

| 检查对象 | 发现 | 本轮结果 |
| --- | --- | --- |
| 原型输入边界 | 候选 `#8998AF` 对白底仅 2.927:1，未达到现有规范 3:1；原型原检查没有覆盖 | 改为 `#8693A9`（3.106:1），新增当前 / 候选外观的核心控件对比度检查；11 组原型检查通过 |
| 样式检查的拒绝能力 | 临时副本中直接色板 `bg-red-500`、任意字号 `text-[11px]` 和内联 RGB 都能漏过；十六进制颜色能被拦住 | 使用已有 TypeScript 解析器识别样式，补 14 个回归样本；上述四种违规均被拦住 |
| 样式检查的误报 | 注释中的 `#abc` 被当成生产颜色 | 跳过注释、JSX 正文和锚点等非样式内容；合法样本和注释样本通过 |
| 运行成本 | 新检查无需 API、数据库或真实目标系统 | 当前本机静态规则 + HTML 样本浏览器检查约 1 秒；是一次本地观察，不是跨环境性能承诺 |

故障注入在临时仓库副本中运行，不改业务源码。当前检查扫描 142 个 TSX 文件、其中 60 个页面文件；这是复查时工作树的数量。原型截图和真实 React 渲染是两种验证，结果分别记录。

### 真实组件抽样发现的待迁移项

在隔离 Vite 页面中加载现有 [Button](../../packages/web/src/components/ui/button.tsx) 与生产 Tailwind / Token，确认实际样式生效后，仅切换 `loading` 属性：

- 带 Check 图标和“保存草稿”文案时，宽度从 104px 增为 128px，图标从 1 个增为 2 个；应在组件迁移中统一图标槽与加载布局。
- 在 `prefers-reduced-motion: reduce` 下，加载图标的 computed `animationName` 仍为 `spin`；需要把该状态接到减少动效约定。
- Disabled 与 `aria-busy` 已随 Loading 生效。以上是现存生产组件与认可原型的差距，不是本次文档或 CI 改动引起的页面回归。

首次复查未修改生产 Button API 或批量迁移业务页。该抽样说明“规范已经写明”和“HTML 样本通过”不能代替真实组件验收。

### 仍需验证的影响

1. **生产样板**：首次复查时尚未迁移；用户随后选择 Target / Scenario，现已完成下面记录的 React 迁移。Run 保持原有业务实现，布局迁移未在本次范围。
2. **skill 行为**：结构校验已通过，分档规则可用；自动选择和成本控制仍由模型执行，未做独立任务的触发率统计。后续用“按钮文案”“局部表单交互”“公共组件”各一次真实任务观察是否分别轻验、局部验和跨页验，不新增全平台验收工程。
3. **CI 环境**：检查命令本地通过、已写入 CI 配置；本轮没有提交推送，也没有观察远端 Linux CI 的实际运行。它会把识别到的样式违规变成检查失败，正常业务接口和运行时行为不受这项接线改变。
4. **静态检查边界**：动态样式、外部 CSS、审美和完整业务能力仍需定向浏览器验收。认证页现存的特殊字号以精确例外保留，迁移时并入 Token，避免把新检查变成无关页面改版。

## Target / Scenario 迁移结果（2026-09-13）

[实际页面截图与验收记录](../front_design/2026-09-13-react-migration/README.md)。

- `tokens.css` 升为 v1.3；四个业务路由使用同一套生产 Token、已有六档字体角色与 Radix 组件。共用样式会影响其他页面的颜色、边界、圆角与阴影；其他页面的业务布局没有批量重写。
- Target：集合摘要、搜索与状态筛选、选中对象概览；详情按账号管理 / 系统资料分区。Scenario：列表显示目标名称与定义版本；详情提供有序步骤、可读输入与断言、输出、策略与结构化定义，保留原有运行弹窗。
- 前端能力边界：保留真实 API、权限与账号隔离；没有新增 AI Executor、完整序列编辑器或版本发布流程。场景手工创建仍限已有三种测试步骤。筛选只覆盖当前 API 返回的集合。
- 迭代发现并修复：加载按钮变宽、减少动效失效、受控弹窗关闭丢失焦点、详情页父导航高亮丢失；场景创建失败保留输入，停用目标不可选，0ms 等待不再被改写。以上用相应浏览器或 Vitest 检查覆盖。
- 验证：设计检查、Web 类型 / 构建、变更业务文件 lint；9 个相关 Vitest 文件共 30 个测试；四个路由的 9 组 Playwright 检查与五档宽度。查看实际桌面与窄屏截图后，将属性面板从默认原始 JSON 调整为可读描述。
- 请求级检查使用固定 fixture，正式页面代码仍调用原 API；没有执行本轮真实后端写入 / 真实目标系统运行，也没有远端 CI 记录。代码与页面表现可以作为后续 AI 开发的样板，完整业务联调继续按相应功能验收。

对应索引与数值已同步回 `docs/design/front/`，不增加新框架、页面生成器或每次小改必跑的完整 UI 验收。
