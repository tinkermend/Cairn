# 识途前端设计规范

版本：v1.6 · 更新：2026-09-24 · 状态：当前设计基线，已接入 Web 全局主题。

2026-09-24 规范升级（v1.6）：基于多轮真实 UI/UX 复盘，全面落地「业务降噪与去技术化（Zero-Jargon）」、「容器自适应与 Dock 伴随布局」、「SaaS 监控看板」、「紧凑微卡（Micro Action Card ≤68px）」、「弹窗视口防溢出」及「现代 AI 交互组件（思考折叠/引导卡片/动作胶囊）」，并确立交付前「双重视角自检清单」。剔除早期实验室原型过渡链接与空头组件，锁定桌面端专业工作台设计基线。

识途采用**冷静蓝白、轻量专业、可观测轨迹清晰的企业级 SaaS 工作台**设计语言。默认浅色；蓝色用于操作和选中，紫色限定于 AI，轨迹、节点、精确边界与克制空间光构成产品视觉签名。

界面建立在**三层平面**上：导航白（`surface-nav`）、内容画布冷灰蓝（`surface-page`）、卡片白（`surface-card`）。三者必须彼此可分辨：
```
卡片白  #FFFFFF   最高层级，承载业务内容与控件
导航白  #FAFBFD   中间层级，连续 L 形导航外壳
画布灰  #F2F5F9   底层基础，纯净冷灰蓝背景
```

## 约束与事实源

- 宪法中[用户控制与信息呈现](../../../CLAUDE.md#用户控制与信息呈现)规定业务信息与用户控制权的边界；色彩、布局、主操作层级及组件规则统一在本目录维护。
- 语义和使用规则以本目录文档为准；可执行的颜色、字体、尺寸值以 `tokens.css` 为准；视觉样本展示应用效果。
- 设计系统使用现有 **shadcn/ui + Radix + Tailwind**。不引入第二套 UI 框架，不重写已有基础交互。
- 新界面统一消费语义 Token。页面不得自选色板、重新定义按钮尺寸或引入独立状态含义。
- 深色主题不属于本轮设计交付；正式接入时明确浅色默认策略，不把现有脚手架暗色变量视为已经完成设计。
- 规范齐全不等于盲目造轮子。组件的当前可复用情况见[落地约定](implementation.md)，缺少的组件按实际业务需求精准补齐，杜绝虚假占位。

## 维护方式

修改共用颜色、尺寸或状态时，同步更新 Token、对应规范与视觉样本。功能模块只引用本规范，不复制一套数值。无法由当前组件表达的真实需求，先判断能否组合已有组件，再补充最小必要的变体。

运行 `pnpm check:design` 可检查文档内部链接、核心色对对比度、源码样式约束、样本交互与桌面布局；已接入 CI 配置，使用项目已有 Playwright，不新增依赖。真实业务页仍需按[工作流](ai-workflow.md)完成浏览器操作与视觉复核。
