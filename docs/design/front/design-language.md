# UI 设计语言

版本：v1.1 · 更新：2026-09-24 · 适用：识途 Web 控制台 · [返回索引](README.md)

## 1. 设计理念

识途是供企业用户长时间使用的专业工作台。设计首先让人看清内容、区分状态、找到操作，再用克制的品牌色建立识别感。

采用冷蓝、冷灰、白色构成稳定底色。白色承载内容，浅冷灰划分工作区，蓝色只强调可操作位置与选中项。AI 与普通功能共享布局和基础组件，仅在能力入口、建议和生成状态处使用少量紫色。

信息密度通过对齐、字号层级、行高和渐进式展开控制，不依赖把文字缩小、隐藏关键字段或移除必要说明。高频信息直接呈现，低频配置在明确的展开入口中提供。

页面首先呈现业务状态，其次是数据趋势，最后是辅助信息。表格用于批量管理，卡片用于概览和快捷操作；具体页面组织按[前端工作流](ai-workflow.md)选择。

### 1.1 识途视觉签名

识途的现代科技感来自“可观测执行”本身：清晰轨迹、连接节点、精确边界、实时状态与克制的空间光。它们共同表达“系统正在被观察、步骤可以追踪、结果可以复盘”，而不是套用抽象的科技装饰。

- **轨迹与节点**：沿用 B 版 Logo 的圆形观测窗口、折线路径和连接节点，只用于品牌区、首次空态和执行进度等少量识别位置。
- **精确边界**：交互控件使用清楚的 1px 边界；Hover 加深。输入 Focus 是主蓝边界加紧贴的半透明外光，不是外扩实线环。最高层级主操作可带一层短距离蓝色投影。
- **空间光与网格**：登录、空态等低信息密度页面可使用静态环境光、32px 细网格和观测环。业务数据页保持纯净表面，不在表格后铺装饰。
- **克制上限**：同一区域最多两层环境光，透明度 6%–10%；网格不超过 4%，并以径向遮罩淡出。禁止持续扫光、粒子漂浮与脉冲背景。

### 视觉取舍

| 采用 | 避免 |
| --- | --- |
| 白色内容面、冷灰细边框、轻阴影 | 大量悬浮卡片、深重阴影、玻璃拟态 |
| 稳定栅格、左对齐、规则间距 | 为构图打散表格、随机尺寸卡片 |
| 单一蓝色主操作、少量紫色 AI 标记 | 多个高饱和主按钮、紫色泛化 |
| 状态文字 + 图标 + 颜色 | 只靠颜色区分结果 |
| 短而明确的中文标签 | 英文模板文案、Lorem Ipsum、含糊的“确定一下” |
| 低密度页使用克制环境光、细网格与精确边界 | 霓虹、玻璃拟态、动态粒子与高饱和渐变 |

### 1.2 降噪与面向业务用户的表达原则（Zero-Jargon & Anti-Redundancy）

识途是业务人员与工程师共同使用的系统。界面表达以任务目标与直观事实为中心，杜绝无意义的技术噪音：

- **禁止直出后端技术标识**：代码层枚举、内部状态名（如 `stage-inspect`、`m_stress`、`HOLDING` 等）、长 UUID、Profile 序列号及中英双重对照不得直接暴露在业务主视图中。必须映射为业务用户能秒懂的清晰中文（如“巡检阶段”、“高负载模式”、“等待接管”）。
- **信息非必要不重复出现**：
  - 左侧或父级列表已清晰表达的属性（如“启用状态”、“所属系统”），右侧详情或附属面板的头部不得以巨幅字号重复堆砌（如反复写“当前系统：XXX”、“状态：启用”）。
  - 同一页面内相同操作（如导入草稿、导出、配置）全页唯一呈现，杜绝在顶栏工具条和步骤区域左侧双重放置相同按钮。
- **表单必填标识轻量化**：字段必填统一在 Label 文本后标注红色半角星号 `*`（使用 `status-error-foreground`），**严禁在输入框前后使用粗暴的红色大汉字（如“【必填】”）**。
- **拒绝自造晦涩术语**：操作授权、准入逻辑等使用业内通用的“权限设置”、“准入规则”，不自造“政策准入控制”等抽象辞藻；不需要用户填写的安全理由直接去除输入框，有权即可配置。


## 2. Design Token 分层

唯一可执行数值表为 [tokens.css](tokens.css)。分为三层：

1. **基础值**：`--primary-600`、`--space-4` 等稳定色号与尺度。
2. **语义值**：`--action-primary`、`--status-error-foreground`、`--surface-card` 等设计意图；组件优先引用这一层。
3. **兼容映射**：`--primary`、`--card`、`--muted` 等现有 shadcn 变量，帮助保留组件 API。

模块不新增“某页面蓝色”或“某页面按钮圆角”。只有跨页面的语义确实不同，才增加共用 Token。`--muted` 保持 shadcn 的浅背景语义，次要文字使用 `--muted-foreground` / `--text-muted`。

**三层平面构成一道明度阶梯，亮度即层级**：画布最暗（最底）、壳居中、卡片最亮（最高）。

```
卡片  #FFFFFF   Y 1.0000
导航  #FAFBFD   Y 0.9641
画布  #F2F5F9   Y 0.9102
```

v1.3 将用户认可的 Foundation 外观接入共用 Token。卡片与画布明度比约 **1.094:1**，导航与画布约 **1.056:1**，卡片与导航约 **1.035:1**。浅边框与克制的双层阴影共同支持业务层次。

三个表面保持不同明度，白色保留给业务卡片与控件。`check.mjs` 检查明度顺序、卡片与画布不低于 1.08:1、相邻两层不低于 1.01:1；调整数值后再看真实页面。

画布不叠渐变。任何环境光铺在大片空画布上都会读成一块擦不掉的脏渍——识途每一页都有大片空画布。
低信息密度的认证页可以用 `technical-*` 那套静态环境光，业务页保持纯净表面。

结构边框可以轻，输入框的必要识别边界不能同样弱。`border-control` 对白底不低于 3:1（WCAG 2.2 SC 1.4.11），
这条由 `check.mjs` 断言卡住：**不得为了观感把输入边界调浅到 3:1 以下**。要让输入看起来更轻，
用平整白底、冷蓝细边和聚焦时的低透明度外光；默认不加内阴影，也不再铺一层浅灰或冷白填充。
`surface-control` 必须与 `surface-card` 同色，由 `check.mjs` 卡住。

### 3.3 语义状态

| 语义 | Accent | 背景 | 文字 / 图标前景 | 表达 |
| --- | --- | --- | --- | --- |
| 成功 / 健康 | `#17B890` | `#EAF9F4` | `#08795F` | 圆形勾 + 明确状态文字 |
| 警告 / 待处理 | `#F59E0B` | `#FFF7E8` | `#925900` | 三角警告 + 原因 |
| 失败 / 错误 | `#F04452` | `#FFF0F1` | `#BD293B` | 圆形叉 + 错误摘要 |
| 信息 / 进行中 | `#3B82F6` | `#EFF6FF` | `#285BC1` | 信息或进度图标 + 状态文字 |
| 等待 / 排队 | — | `#EDF2F8` | `#526681` | 时钟 + 等待文字 |
| 阻塞 | — | `#FFF1E8` | `#BA4918` | 阻塞图标 + 原因 / 所需操作 |
| 跳过 / 中止 / 中性 | — | `#F4F6FA` | `#526174` | 各自图标与各自文字，不合并文案 |
| AI 能力 | `#7C5CFC` | `#F2EEFF` | `#6444D4` | Sparkles + 能力名称或生成状态 |

Accent 用于进度段、图形填充和装饰强调，不直接用作浅底小字号文字。失败按钮使用深红 `status-error-foreground` 配白字。

状态色提供三种标准使用范式与直觉别名：
1. **实体强调态（`bg-status-*` / `var(--status-*)`，映射自 Accent）**：用于进度条填充（Progress）、状态胶囊段（SegmentedStatusBar）、状态圆点（Status Dot）和时序图线。与基础别名打通，符合常规编码直觉。
2. **柔和容器态（`bg-status-*-background`）**：用于状态徽章底色、告警横幅、就绪/阻塞提示卡片背景。
3. **文字前景色（`text-status-*-foreground`）**：用于浅底容器上的状态文字与高对比度警示标签。

监控与态势感知大盘遵循动态色阶与异常聚焦规范：
- **执行通过率 / SLA**：≥95% 为健康松石绿（`bg-status-success`）；80%~94% 为警示琥珀黄（`bg-status-warning`）；<80% 为危险珊瑚红（`bg-status-error`）。
- **容量与负载水位**：<60% 为稳定冷蓝（`bg-primary`）；60%~80% 为警戒暖黄（`bg-status-warning`）；>80% 为满载高危红（`bg-status-error`）。
- **异常聚焦与降噪**：为 0 或畅通无事时保持静默低噪（淡灰色数字或微绿底），有异常/积压/失败（>0）时采用醒目的警示药丸（Alert Pill，如浅红底+红字+边框）高亮呈现，支持一键下钻定位。

状态呈现与态势感知遵循三项通用指引原则：
1. **正向确认与状态闭环（Positive Confirmation）**：确定性执行与可观测平台中，“正常”不是默认静默留白，而是给用户的安全感闭环。对于代表最终结果的列、卡片与关键状态，正常/完成状态需具备轻柔且明确的正向色彩反馈（如浅绿徽标、极浅状态衬底），做到“正常看得见、异常跳得出”，拒绝无效留白。
2. **实体 Accent 与文字 Foreground 的分担边界（Surface Hierarchy）**：裸图标、状态圆点、图形轨迹与进度条属于实体图元，统一消费明亮通透的实体 Accent（如 `text-status-success`、`bg-status-error`）；只有当存在浅色状态容器包裹（如 Badge/Banner）时，其内部文字才消费 `-foreground`（保证文字阅读对比度）。
3. **聚合态与占比指标的“分段化与色阶化”（Adaptive & Segmented）**：指标呈现优先赋予业务态势感知。包含多种结果维度的集合指标（如批处理、流水线耗时），优先采用多段彩色分割条；单值健康度与达成率指标（如 SLA、算力利用率），必须根据阈值自适应动态色阶（绿/黄/红），避免单色灰度贯穿。

红色仅表达失败、错误与危险；紫色仅表达 AI 能力，不用作普通功能或其他业务状态的强调色。

进行中不意味着成功；排队不是警告；用户主动中止不是系统失败；部分完成不能涂成全绿。超时可以沿用错误语义，但文字保持“已超时”。重试使用警告色和“重试中”，最终结果由持久化事实决定。这是展示词汇约定，不新增或修改运行时状态枚举。

## 4. 字体与排版

| 层级 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面标题 | 24 / 32px | 600 | 每页一个 h1 |
| 模块标题 | 16 / 24px | 600 | h2 与主要分区 |
| 关键数字 | 28 / 36px | 600 | 统计卡重点值 |
| 正文 | 14 / 22px | 400 | 主要阅读内容 |
| 辅助说明 | 13 / 20px | 400 | 提示、说明、次级文本 |
| 表格内容 | 13 / 20px；舒适密度 14 / 22px | 400 | 同一表格保持一致 |
| 标签 | 12 / 18px | 500 | 状态、标签、紧凑元信息 |
| 代码 / 标识 | 12–13 / 20px | 400 | 选择器、JSON、技术标识 |

字体栈：Inter → 系统拉丁字体 → PingFang SC → Microsoft YaHei → Source Han Sans SC → system-ui → sans-serif。
Inter 拉丁子集已自托管在 `packages/web/public/fonts/`（可变字重 400–700，SIL OFL 1.1），`@font-face` 在 `styles/index.css`。
CJK 不由 Inter 承担，回落到系统中文字体。不引用外部字体服务，不让字体服务成为控制台打开的必要条件。

字号刻度以 `--font-size-*` / `--line-height-*` 为准，并映射到 Tailwind 的 `--text-*` 命名空间，
页面使用 `text-page`、`text-section`、`text-stat`、`text-body`、`text-small`、`text-label`。
不映射就等于没有：只写在 tokens.css 里、没有接进 `@theme` 的字号刻度，页面永远消费不到。

**刻度的适用范围是页面层**，即 `features/` 与 `components/layout/`：这些文字有明确的内容职务
（页面标题、模块标题、正文、辅助说明、标签），必须落在上表里，由 `check.mjs` 断言卡住。

`components/ui/` 是 shadcn 组件底座，其中的 `text-sm` / `text-xs` 是**控件字号**而不是内容职务——
下拉菜单项、对话框描述、表单校验信息属于控件自身的排版。把它们一律换成 `text-body`（正文 14/22），
等于给菜单项赋予"正文"语义，是另一种错。组件底座沿用 Tailwind 默认刻度，不纳入这条断言。

数字、时间和金额开启 `font-variant-numeric: tabular-nums`。表格数值列右对齐并在列标题说明单位；主文本左对齐；状态标签左对齐；操作列保持固定位置。不要把所有单元格居中。

标签和按钮尽量使用短动词。中文不使用大字距，**也不使用负字距**——负字距是按 Inter 拉丁字的 tracking 调的，
套到中文会挤压字身；含中文的标题一律不加 `tracking-tight`。正文不小于 13px。长内容换行或明确省略，省略项提供可聚焦的展开 / 复制方式；关键错误原因、完整表单值不得仅存在于 Hover Tooltip 中。

页面正常文本允许用户放大，200% 缩放后不得丢失操作。长标识可用 `overflow-wrap:anywhere`；表格列的省略仅限制显示，不改变原始数据。被截断的单元格必须在悬停和聚焦时用 Tooltip 给出全文。

## 5. 间距与密度

基础步长为 4px。允许值为 4、8、12、16、20、24、32、40、48px；1px 边框和光学微调不受此步长约束。

这一档数值与 Tailwind 默认刻度完全重合，因此**不在 tokens.css 里重复声明**间距、控件高度与表格行高；
直接用 `p-4`、`gap-6`、`h-9`、`h-12` 等工具类。tokens.css 只保留 Tailwind 覆盖不到的值。

| 场景 | 规范 |
| --- | --- |
| 图标与文字 | 8px；紧凑标签 4px |
| 标签与表单控件 | 8px |
| 控件与说明 / 错误 | 4–8px |
| 同组控件 | 12–16px |
| 表单项垂直间距 | 16px |
| 主业务容器 / 外层卡片 | 20px（`p-5`），用于外层卡片与大设置面板 |
| 紧凑面板 / 数据表外框 | 14–16px（`p-3.5` ~ `p-4`），用于数据表外框与分段检查器 |
| 微型卡 / 复合列表项 | 8–10px（`p-2` ~ `p-2.5`），用于助手导览卡、工作台步骤、子选项，单卡高压制在 56–68px |
| 卡片间距 | 12–16px；紧凑列表间距 8px |
| 模块间距 | 20–24px |
| 页面左右边距 | 1366 / 1440px 使用 24px，1920px 使用 32px |
| 对话框内边距 | 20–24px；微型弹窗采用 16px |

密度梯队与业务场景强相关：数据表提供 32 / 36 / 40 / 48px 四档行高。高密度专业工作台（Studio 步骤管线、Attempt 证据列表、数据行）默认 32–36px，保证首屏信息可见度；常规后台主从管理表默认 40–48px。

## 6. 布局基础

桌面设计基准为 1440px。识途是企业级专业工作台，基准宽度为 1440px，全面支持 1366px 常见桌面与笔记本，1024px 为紧凑断点下限。不承诺为 768px 以下的手机端提供重型工作台降级，杜绝虚假移动端适配带来的冗余代码。Shell 使用 208px 侧栏（可收起为 72px 图标栏）与 56px 顶栏（`h-14`）；内容区遵循 12 栅格，相邻模块共用左右边界。通用 Shell 约定不等于规定具体模块布局。

**壳是连续的，内容嵌在壳里。** 侧栏与顶栏同为 `surface-nav`，二者构成一个连续的 L 形外壳，
**壳内部不得出现任何切割线**——侧栏不画右边框，顶栏不画下边框，否则顶栏会读成一个单独停靠在侧栏旁边的盒子。
边界只画在内容面板自己身上：面板铺 `surface-page`，左边与上边各一条 `border-default` 描边，左上角 16px 圆角。
壳与内容因此各自成立：壳负责导航与身份，内容面板负责业务，用户一眼能分清哪一块会随页面变化。

| 宽度 | 侧栏 | 页面边距 | 内容处理 |
| --- | --- | --- | --- |
| 1920px 及以上 | 208px，可收起至 72px | 32px | 数据区与画布充分展开；长阅读文本最大约 72ch |
| 1440–1919px | 208px，可收起至 72px | 24px | 默认桌面形态，栅格间距 20px，支持三栏 Studio 展开 |
| 1366–1439px | 208px，可收起至 72px | 24px | 栅格间距 16px，高密度紧凑工作台标准视口 |
| 1024–1365px | 默认收起为 72px，用户可展开至 208px | 20px | 笔记本紧凑断点；辅助面板转抽屉或折叠次要操作 |
| 小于 1024px | 提示切换大屏 / 抽屉侧栏 | 16px | 移动端提供汉堡抽屉导航，顶栏自适应收敛为图标按钮 |

不得让页面整体横向滚动。列宽确实不能缩小时，表格自身横向滚动并显示滚动提示；保留名称 / 选择列与操作可达性。不要仅用 `overflow-x:hidden` 掩盖布局错误。筛选与其作用的数据表、分页必须落在同一张卡片上，筛选做成表头工具栏，不要在页面背景上另做一张表单。会持续增长的表格默认服务端分页，规则见[组件规范 · 增长表的分页底线](components.md#增长表的分页底线)。

侧栏：展开宽 208px，常驻区 5 组（总览、编写、运行、目标、运维），一级导航 36px 高、图标 18px；当前项为浅蓝底、深蓝文字和可感知的选中标记；底部提供「系统与管理」入口（弹出面板展示平台运行概况与管理导航）。折叠为 72px 图标栏后保留 Tooltip 和可访问名称，当前项不能只靠文字消失前的位置记忆识别；窗口高度不足时导航区域独立纵向滚动，入口不可被裁切。

顶栏：高度 56px（`h-14`）。左侧为移动端侧栏开关与面包屑（支持详情页动态注册实体名并截断长名称）；右侧依次排布紧凑查找入口（≤240px，含平台对应快捷键）、识途助手入口（带状态圆点与快捷键）以及最右侧 30px 头像（触控区 ≥ 44px，展开账号菜单与退出确认）。长项目名称需截断并可查看完整名称。

页面结构以标题 / 说明、核心操作、筛选、主内容、辅助内容为基本顺序。多栏编辑器可按工作任务重排，但键盘顺序应与阅读顺序一致。内容滚动时，被固定栏遮挡的焦点必须滚入可见区域。

### 6.1 认证页

认证页在 1024px 及以上采用左右等宽布局，页面内边距与栏间距均为 24px。整体背景从左侧近白自然过渡到右侧浅蓝，叠加少量静态环境光，与配图底色衔接。左侧品牌、登录表单与页脚直接置于连续背景上，不加卡片底、边框、圆角或阴影；仅右侧配图保留圆角卡片。表单最大宽 400px，垂直居中。Logo 为 64px，与字标间距 16px；品牌名 28/36px，副标 14/24px，两行间距 4px，总高度与图标对齐。小于 1024px 时隐藏右栏，表单改为单列；低高度视口允许自然纵向滚动，不裁切错误信息或主操作。

右侧使用已确认的[立体执行轨道配图](../../../packages/web/src/assets/brand/login-execution.webp)，以浅蓝底、圆角和一句产品主张表达 AI 与确定性操作的融合执行。品牌配图标题使用 28 / 34px，保持为可选取的 HTML 文本，不烘焙到图片；不再添加底部说明段落。通过原生 picture 的媒体条件让窄屏不下载装饰配图。

登录副标题为“智能场景执行平台”。用户确认的局部动效仅用于右侧配图：节点依次点亮、轨道光点前进、小面板浮现；背景、平台主体和标题保持稳定。静态图先显示，分层资源解码后增强，单轮约 6.3 秒，移入右图可重播；后台暂停，减少动态效果时保留静态图。实现及素材约定见[品牌规范](brand.md#登录配图)。

认证输入、密码显隐操作与主要按钮统一为 48px 高，输入和按钮沿用控件圆角及共用 Focus / Error / Loading 状态；登录是唯一最高强调操作。配图是装饰，关键产品含义由相邻文字提供。

### 6.2 容器自适应与多栏 Dock 挂靠规范（Container-Aware Layout）

识途大量工作台（Studio 编排、Run 运行复盘、知识地图等）包含侧边停靠面板（如识途助手 Dock，宽度 380–600px）或可拉伸详情抽屉。此时页面内部的排版规则必须从“纯视口断点”转向“容器自适应”：

- **优先使用容器查询（`@container`）而非视口媒体查询**：
  - 工具栏、表单网格与卡片列表的断点必须依据其父容器实际渲染宽度计算。
  - 当右侧助手展开使主工作区宽度被挤压至 800–1000px 时，顶部工具栏次要操作自动收纳进「更多操作（...）」下拉菜单，主操作保持可见，**严禁发生按钮错乱、断行或撑破页面宽度**。
- **独立高度与双轴滚动隔离（Scroll Containment）**：
  - 并排的多栏（如全景海域画布 vs 右侧知识资产列表）外层容器必须有固定或计算高度（`h-[calc(100vh-...)]`），两栏内部各自使用 `overflow-y-auto` 或 `ScrollArea`。
  - **严禁右侧数据列表的长内容把整个页面的外层容器与左侧图形海域拉伸出数千像素**。

## 7. 圆角、边框与阴影

| 对象 | 圆角 | 边框与阴影 |
| --- | --- | --- |
| 标签 | 6px | 通常无阴影；状态用浅底 |
| 输入 / 按钮 | 9px | 1px 边框；输入默认平整无内阴影，聚焦用 `control-focus-shadow`；主按钮用 `action-shadow` |
| Select 下拉面板 | 9px | `border-menu` 冷蓝细边 + `menu-shadow`；选项状态见组件规范 |
| 业务容器 / Card | 14px | `border-card` 极浅边框 + `shadow-card` 双层阴影 |
| 集合摘要统计卡 | 20px | 冰川蓝浅渐变、柔和阴影与层叠图标底座；由 `summary-*` Token 和公共组件提供 |
| Modal / Drawer | 18px | `shadow-popover`；Drawer 仅外露角圆角 |
| Avatar / 小状态点 | 50% | 仅圆形对象使用，不传播给所有组件 |

**轮廓与层次分工明确**：浅色卡片采用 1px 低饱和冷边（`border-card`）清晰界定几何轮廓，配合极柔和的双层弥散阴影（`shadow-card`，接触影 `0 2px 4px` + 环境影 `0 10px 28px`）建立表面浮起感；严禁使用深重黑色粗糙阴影或高对比实线粗框。

用户于 2026-09-23 选定 **B1 · 冰川蓝（柔和立体）**。集合摘要采用 `summary-card-background` 的瓷白到冰蓝渐变、36/44px 关键数值与 36px 层叠图标底座；宽桌面提升为 40/48px 数值与 40px 底座。右上图标不撑高标签行，说明不预留空行，常见桌面卡高约 140–148px。数值保持深蓝纯色，渐变只承载表面光感。该外观由 `CollectionSummary` 统一提供，普通业务容器仍按上表的 Card 规则组织；全局 `surface-card`、`card-shadow` 与 `font-size-stat` 不承担集合摘要的专用样式。
1px 浅边框叠 4% alpha 阴影是失败组合——边框撑不住、阴影浮不起来，卡片会读成线框图里的方框。

主按钮携带 `action-shadow`（蓝色投影），这是平台主操作的视觉签名，不再只出现在认证页。

卡片 Hover 只在卡片本身可点击时增强边界，可轻微上移（≤2px）并换用更强的阴影；`prefers-reduced-motion` 下取消位移。静态数据容器不因 Hover 浮起。按钮、开关和导航项使用 2px 蓝色外环与 3px 间隔。输入、文本域和选择器使用 1px 主蓝边界加紧贴的 3px、约 10% 透明度外光，避免白底上出现粗一圈的外扩实线。两者都不能只改变边框，也不能移除浏览器焦点而无替代。

Active 使用颜色或内侧阴影反馈，不移动布局。弹层遮罩使用 `--scrim`，只降低背景视觉权重，弹层正文保持白底。

认证等高聚焦面板与可点击卡片的 Hover 态可使用 `tech-panel-shadow`；普通静态业务卡片和工具栏按钮不使用这种强调阴影。环境网格、观测环与光晕只读取 `technical-*` Token，页面不自行配置另一组色值。

## 8. 图标

沿用项目已安装的 **Lucide**，统一线性样式。默认 18px / stroke 1.75；按钮 16px；顶栏与空状态局部 20–24px。不要混用多套图标或用 Emoji 替代正式界面图标。

集合摘要使用 20px / stroke 1.75 的图形，宽桌面为 22px，放在冰蓝渐变底座中。底座轻微旋转与层叠，图形保持正向。尺寸由共用样式统一，调用方已有的成功、警告等语义色保留。数字卡的装饰图标不新增独立交互。

图标使用 `currentColor`，普通功能保持中性色或主色；只有状态与 AI 使用语义色。不为每个模块配置独立彩色图标。

模块入口卡片的图标砖为 44px、12px 圆角、主蓝渐变底配白色图标，并带 `action-shadow`。
这是入口卡片承载视觉重量的方式——所有入口共用同一套主蓝，仍然不按模块分配不同色相。

纯图标按钮必须有中文可访问名称；Tooltip 在 Hover 和键盘 Focus 均可见。相邻文字已表达含义的图标设为 `aria-hidden`。具备业务含义的图标配文字，不靠图标形状让新用户猜测。

## 9. 图表规范

使用已有 Recharts，不为基础统计另加图表库。颜色顺序在所有普通类别图中统一：

| 序号 | Token | 值 |
| --- | --- | --- |
| 1 | `chart-1` | `#245CE5` |
| 2 | `chart-2` | `#168779` |
| 3 | `chart-3` | `#576D92` |
| 4 | `chart-4` | `#8A6C22` |
| 5 | `chart-5` | `#4D7890` |

同一实体跨图保持同一颜色，不能因排序变化重新染色。超过五组优先 Top N + 其他、筛选或拆图。紫色不作为普通图表的默认系列色。

**状态分布优先语义映射，覆盖普通顺序色板**：成功绿、失败红、进行中蓝、等待灰蓝、警告橙、跳过灰。颜色仍配合标签、图例、线型或图案，所有图提供可读取的数据表 / 摘要。

| 图表 | 规范 |
| --- | --- |
| 折线图 | 主线 2px；次线使用虚线；坐标轴说明单位、周期、时区；Hover/Focus 可读值 |
| 柱状图 | 数量轴从零起，柱间距规则，值过长用横向柱图；避免 3D |
| 堆叠柱图 | 固定堆叠顺序，区分数量与百分比，100% 图以 0–100% 为轴 |
| 环形图 | 最多五类；中心显示总数或明确口径；图例含数量与比例，极小扇区不能隐藏 |
| 趋势迷你图 | 不用于精确读数；与相邻数字、变化值和时间范围一起出现 |
| 结果分布图 | 状态映射一致；运行中与已结束数据分开标明口径 |
| 成功率趋势 | 默认 0–100% 轴；局部放大必须明显标注区间；定义分母、排除项与无数据情况 |

空数据与零值分开：无样本显示“暂无数据”，不显示 0% 假结论。缺失时段折线断开，不能插值成真实结果。Tooltip 给出精确值，图例与键盘入口不能只在鼠标靠近时存在。

### 9.2 SaaS 监控看板与态势视图规范（Operational Dashboard）

监控看板用于实时呈现平台与执行节点的运行态势，杜绝无审美的“数值方框堆叠病”：

- **图表优先而非空洞数值框**：
  - 队列积压、处理延迟、AI 调用频次、成功率等连续型指标，优先使用带平滑曲线的面积图、柱状图或趋势迷你图（Sparkline），辅助展示当前最新值与对比变化。
  - 仅有当前计数的离散值（如当前存活节点数），采用紧凑微卡片，禁止铺设无数据沉淀的大尺寸空白方框。
- **顶栏控制带紧凑收口**：
  - **运行健康状态**：使用紧凑微型状态灯（绿色脉冲/健康、黄色告警、红色异常）收纳于顶栏右侧，杜绝占用大面积横幅 Banner。
  - **控制项归拢**：配置规则按钮、数据截止时间、自动刷新频率选择器（15s / 30s / 60s / 120s / 暂停）与手动刷新按钮必须整合成单行紧凑控制带，并排置于页面标题栏右侧。
- **局部静默更新（Silent Delta Refresh）**：
  - 自动轮询只触发图表与数据项的静默局部重新渲染（只更新 series 数据），**严禁触发全页面级骨架屏或刷新闪烁**，保证用户的阅读位置与滚动条绝对稳定。

## 10. 动效与无障碍

微交互 150ms，面板进出 220ms，使用统一缓动。动效只用于说明状态变化；不使用持续脉冲背景、弹跳图标或数据进入时的长动画。尊重 `prefers-reduced-motion`，生成 / 加载即使停止旋转仍有文字说明。

**不得使用 `transition-all`。** 过渡必须写明属性表，例如 `transition-[background-color,border-color,box-shadow]`。
`transition-all` 会把没打算动的属性一起动画掉——包括影响布局的那些——等于动效不解释任何东西。
这条由 `check.mjs` 断言卡住。

验收目标：普通文字对比度至少 4.5:1，大字至少 3:1，必要控件边界和状态识别至少 3:1。可见焦点不被固定内容遮挡；可拖拽交互同时提供上移、下移等不依赖拖动的操作。这些要求依据 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)，本规范不把示例检查当作完整合规认证。

桌面按钮使用 32 / 36 / 40px 三档；触控场景扩大点击区域至至少 44px。键盘能够完成所有必要交互；对话框管理焦点与返回位置；状态变化通过适当的 `aria-live` 提示，避免每次进度变化重复播报。
