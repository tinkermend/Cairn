## 四个评审入口

| 入口 | 可以实际操作 | 重点判断 |
| --- | --- | --- |
| [组件与交互](index.html#components) | 表单校验、加载与报错、策略保存、弹窗、侧栏、菜单、可点击卡片 | 主操作是否突出，聚焦与错误反馈是否清楚，动效是否克制 |
| [目标系统](index.html#targets) | 搜索筛选、选择详情、新建目标、添加独立目标账号 | 批量管理与对象详情是否容易切换，账号与会话含义是否明确 |
| [场景编排](index.html#studio) | 添加与移动步骤、编辑属性、接受 AI 建议、保存、模拟试跑 | 步骤序列、属性与试跑能否在同一工作区连贯完成 |
| [运行复盘](index.html#run) | 切换步骤与 Attempt、放大证据、查看输入输出及事件、读取快照、认证与人工核查 | 是否容易回答哪一步、哪次尝试、什么结果、什么证据 |

## 建议用这五条路径评审

1. 在组件页修改场景名称，输入错误地址，点击保存；观察错误信息、修正后反馈与加载时按钮宽度。切换顶部“当前 Token / 候选方案”，比较同一内容。
2. 在目标页选中客户服务系统查看待认证状态；接入一个虚拟目标并添加目标账号，观察列表与详情关系。
3. 在编排页修改 AI 提取意图，接受一条 AI 建议，移动步骤并保存。点击“模拟试跑”，试跑启动后继续改步骤名称；打开运行快照，确认快照仍然保留启动时的名称。
4. 在运行页选择“重试后成功”，分别点击 Attempt 1 / 2。再切换“证据不完整”，观察成功结果和证据缺失同时存在。
5. 切换“副作用待核查”“等待目标认证”“实时连接中断”，检查每个状态对应的动作；再试紧凑密度、收起导航和减少动效。

## 比较范围

“当前 Token”直接引用 `docs/design/front/tokens.css`；“候选方案”只在此目录局部覆盖蓝色、表面、边界、圆角、阴影与动效时长。**两种模式共用本轮设计的新布局与交互，不等于旧生产页面与新页面的完整对照。** 现有组件样本可从页脚打开。

当前原型的数据在浏览器内存中保存，刷新恢复初始示例。模拟试跑不执行输入的指令或表达式，不访问目标系统。页面证据采用 HTML 示意画面，已明确标记，并非真实采集截图。主题切换不重置业务数据。

## 评审后如何沉淀

这一轮先判断三层是否成立，再推进正式底座：

| 层次 | 本轮验证 | 后续收敛位置 |
| --- | --- | --- |
| 视觉规则 | 语义色、文字层级、表面边界、交互反馈 | `docs/design/front/tokens.css`、`design-language.md` |
| 组件状态 | 默认、聚焦、加载、禁用、校验、错误、弹层关闭后的焦点 | `components.md` 与现有 shadcn / Radix 组件 |
| 业务布局 | 管理页的列表与详情、编排页的序列与属性、复盘页的步骤与证据 | `implementation.md` 中的页面组合规则和验收后的真实页面范例 |

未来 AI 开发页面时，应先写清任务、主操作、核心领域对象与异常状态，再选择管理页或工作区布局，最后组合现有组件。尤其应把“Attempt 失败但 StepRun 成功”“执行成功但 Evidence 不完整”“未绑定 Target 不可执行”等真实状态作为生成页面的验收案例。

正式迁移可先选一个管理页和一个工作区试点，确认交互、信息密度和真实数据接入后的效果，再更新统一规范。该目录不成为生产组件来源，也不新增一套 UI 框架。

可以直接用浏览器打开 `index.html`，无需构建或安装新依赖。保留目录相对位置以复用项目已有 Token、字体与 Logo。图标由项目现有 Lucide 包在制作时嵌入 HTML。

从仓库根目录运行：

```sh
node docs/front_design/2026-09-13-foundation-lab/check.mjs
```

检查会更新 [screenshots/](screenshots/) 下四张 1440 像素宽度的页面截图。这些是 HTML 的浏览器截图，不计入此前生成的概念图。
