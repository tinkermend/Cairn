现在请基于 UI 规范，对现有前端项目进行重构。

在修改代码前，先完成以下工作：

1. 分析当前技术栈、目录结构、路由结构和组件依赖；
2. 识别当前项目中的：
   - 全局颜色
   - 字体
   - 间距
   - 圆角
   - 阴影
   - 按钮
   - 表单
   - 表格
   - 弹窗
   - 状态标签
   - 页面布局
3. 找出重复组件、硬编码样式和不一致的设计；
4. 输出 UI 重构计划；
5. 输出会被修改的文件清单；
6. 在获得确认前，不要直接大范围删除或重写业务代码。

重构时遵循以下原则：

- 保留现有接口调用；
- 保留现有路由；
- 保留状态管理逻辑；
- 保留权限控制；
- 保留表单校验逻辑；
- 不修改后端数据结构；
- 不修改测试任务的业务流程；
- 将视觉样式逐步迁移到统一的 Design Token；
- 优先封装公共组件，避免页面内重复实现；
- 不要在 JSX、Vue Template 或页面文件中大量硬编码颜色；
- 所有颜色、圆角、阴影和间距都从主题变量获取；
- 每完成一个阶段，确保项目可以正常编译和运行。

请分阶段实施：

阶段一：
建立 Design Token、全局主题、字体和基础布局。

阶段二：
重构 Button、Input、Select、Tabs、Tag、Card、Table、Modal、Drawer 等基础组件。

阶段三：
重构全局侧边栏、顶部导航和页面容器。

阶段四：
先改造 Dashboard 作为样板页面。

阶段五：
补充空状态、加载状态、错误状态和响应式适配。

每个阶段结束后请输出：

- 已完成内容
- 修改文件
- 组件变化
- 是否影响业务逻辑
- 尚未完成内容
- 需要人工确认的问题
